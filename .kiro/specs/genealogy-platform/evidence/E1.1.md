## Decisions

- ADR-E0.5-01: pinned Java 21 (latest patch), Spring Boot 3.3.4,
  Gradle 8.10, Node 22 LTS, PostgreSQL 16, jOOQ 3.19.13, Flyway 10.20,
  OpenTelemetry 1.42, Testcontainers 1.20.
- Convention plugins are delivered as Gradle script plugins
  (`gradle/conventions/*.gradle.kts`) rather than compiled
  `java-gradle-plugin` artifacts. E1.1 evaluated the compiled
  plugin route first but the included composite build required Kotlin
  / Groovy compilation that added friction without delivering
  concrete value at the 25-subproject scale. Script plugins evaluate
  directly via the Kotlin DSL with no compile step; E1.2 can migrate
  to compiled plugins if friction becomes painful.
- `rootProject.name = "genealogy-platform"` is applied via
  `settings.gradle.kts`. The first call to `./gradlew projects`
  surfaced a Kotlin DSL behaviour where the assignment was silently
  ignored; root cause was the early `repositories { mavenCentral() }`
  declaration in `build.gradle.kts` conflicting with
  `RepositoriesMode.FAIL_ON_PROJECT_REPOS`. Moving repositories to
  `settings.gradle.kts` fixed the issue and produced the 21-project
  tree expected.
- Dependency verification metadata is intentionally absent for E1.1.
  ADR-E0.5-01 §Security/privacy puts SBOM + Cosign in E1.6; until
  then Renovate `vulnerabilityAlerts: enabled` is the primary
  security gate. `gradle/verification-metadata.xml` will be added
  in E1.6 alongside the keyring.
- `boundary-check.mjs` is implemented in Node.js (not Bash / jq) so
  that pnpm-workspace CI agents can consume it as a single-file
  standalone script. The script's regex was extended during testing
  to also match Java/Kotlin `import a.b.c;` statements, not just
  TypeScript `from "..."` imports.

## Residual risks

- Dependency verification (`gradle/verification-metadata.xml`) is
  intentionally absent until E1.6 wires SBOM + Cosign. Renovate
  `vulnerabilityAlerts` is the only supply-chain gate at this stage;
  the absence is documented and tracked.
- Convention plugins are script plugins, not compiled
  `java-gradle-plugin` artifacts. This trades reusability ergonomics
  for build simplicity; if a downstream epic adds a 3rd+
  cross-cutting concern that needs dynamic configuration, switch
  to compiled plugins in a dedicated task (proposed E1.7).
- Per-subproject `gradle.lockfile` has been generated for
  `tenant-service` and `genealogy-service` only. The full
  monorepo lockfile matrix lands in E1.2 alongside the
  `gradle --write-locks` quality command.
