## Changes

### Shared auto-configuration library
`libs/platform-spring-boot-starter` (new Gradle subproject)

- `build.gradle.kts` — applies `org.springframework.boot` +
  `io.spring.dependency-management`; declares the `spring-runtime`
  + `spring-data` + `observability` bundles; pulls the
  OpenTelemetry Spring Boot starter (Micrometer bridge); pulls
  the cross-cutting libs (`platform-errors`,
  `platform-telemetry`, `platform-security`,
  `platform-feature-flags`).
- `PlatformProperties` (`@ConfigurationProperties("platform")`)
  — binds `platform.tenant.{header-required,max-id-length}`,
  `platform.security.{issuer-uri,audience,require-bearer-token}`,
  `platform.audit.{enabled,metric-name}`,
  `platform.openfeature.{provider,flagsmith-*,cache-ttl-millis}`,
  `platform.shutdown.timeout-seconds`,
  `platform.otel.{service-name,exporter-endpoint,always-sample}`.
- `PlatformSpringBootAutoConfiguration` — top-level `@Configuration`
  with `@ComponentScan` over every piece of the starter; registered
  via `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.
- `AuditAutoConfiguration` — installs
  `MicrometerAuditPublisher` (counter + structured log) unless
  the service supplies its own `AuditPublisher` bean. Disable
  via `platform.audit.enabled=false`.
- `OpenFeatureAutoConfiguration` — installs
  `dev.openfeature.sdk.NoOpProvider` so the service always
  starts, then wraps the SDK in `SafeFeatureClient` whose
  `getBoolean` / `getString` never throw and always return
  the default value when the provider is unavailable. The
  Flagsmith provider is wired in E2.8 — the `NoOpProvider`
  default keeps the service in a safe state in the meantime.
- `TrustedContextAutoConfiguration` + `TrustedContextFilter` —
  servlet filter at `Ordered.HIGHEST_PRECEDENCE + 20` that
  extracts `X-Tenant-Id`, generates / propagates
  `X-Correlation-Id`, populates the `TrustedTenantContext`
  thread-local and writes both to the SLF4J MDC. Returns
  `400` with `application/problem+json` when the tenant
  header is missing (the default) or too long. Skips the
  Spring Boot Actuator probe paths so health checks don't
  need a tenant.
- `TrustedTenantContext` — thread-local holder; `set(ctx)`
  / `clear()` are called by the filter; `current()` returns
  the safe empty context when unset so services can refuse
  to act when the request is unauthenticated.
- `AuditEvent` + `AuditPublisher` interface +
  `MicrometerAuditPublisher` implementation. The interface
  decouples consumers from the publisher so the dedicated
  `audit-service` integration (Kafka topic + idempotent
  inbox) can land in E3.6 without consumer changes.
- `META-INF/genealogy/platform-spring-boot-defaults.yml` —
  ships the production-safe defaults so a service only
  has to depend on the starter to inherit them.
- `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` —
  registers the four auto-configurations.
- `src/main/resources/logback-spring.xml` — structured pattern
  with `tenant_id` + `correlation_id` MDC keys so every log
  line is tenant-aware.
- `src/test/java/.../PlatformSpringBootStarterTest.java` —
  5 unit tests covering property defaults, audit counter
  increment + disable, trusted context defaults, safe
  feature flag fallback. All 5 pass.

## Decisions

- **Auto-configuration as a Gradle library, not a Spring
  Boot starter `.jar`.** The Spring Boot starter convention
  is to ship a separate `META-INF/spring/...AutoConfiguration.imports`
  jar; the monorepo's cross-cutting libs are already Java
  libraries and the E1.4 template is just another
  subproject. The `AutoConfiguration.imports` file ships
  the same contract — the difference is purely Gradle
  packaging.
- **No client-supplied `tenantId`.** Both the OpenAPI
  contracts and the protobuf `Context` message carry the
  tenant id as a server-derived value. The
  `TrustedContextFilter` rejects requests that don't carry
  `X-Tenant-Id` (when `platform.tenant.header-required=true`,
  the default). The same rule is enforced by the
  `scripts/test-contracts.mjs` Node test (item #10).
- **OpenFeature safe fallback.** The starter always
  installs `NoOpProvider` so the service starts when
  Flagsmith is unreachable. A dedicated provider is wired
  in E2.8. The `SafeFeatureClient` never throws so a
  missing provider can't break a request.
- **Audit publisher as an interface.** The
  `MicrometerAuditPublisher` is the E1.4 default; the
  dedicated Kafka-backed publisher lands in E3.6. The
  `AuditPublisher` interface decouples consumers so the
  swap is a one-line change in the service config.
- **Test fixtures via `java-test-fixtures` plugin.**
  Testcontainers should not be on the production
  classpath. The Gradle `java-test-fixtures` plugin is
  the standard solution and keeps the production
  classpath lean.
- **Integration test isolation.** A separate `integrationTest`
  source set + Gradle task keeps the Docker-dependent
  tests out of the `pnpm test:contract` + `pnpm check:java`
  aggregate. Developers without Docker opt out with
  `-Dskip.it=true`; CI runs both. The dedicated
  `checkstyleIntegrationTest` task follows the same flag.
- **gRPC port bound but service not yet implemented.**
  The `spring-boot-starter-grpc` is on the classpath so
  the gRPC port is bound on startup; the full
  `TenantServiceImplBase` lands in E3.2 once E4 fixes the
  remaining protobuf enum collisions in the `genealogy`
  package.
- **Cross-package enum collisions in protobuf.** E1.3
  ships the contracts but `protoc` rejects files where two
  sibling enums in the same Java package share value
  names. The `tenant/v1/tenant_service.proto` collision is
  fixed in this PR (the enum values were already
  unique-ish — just missing the `enum_value_scope` flag
  that the E1.3 build never exercised). The
  `genealogy/v1` collisions (`Visibility` in
  `tree_service.proto` + `person_service.proto`) are
  flagged in the E1.4 evidence and fixed in E4.

## Security and privacy

- Tenant isolation: PASS — `TrustedContextFilter` is the
  only place where `tenantId` enters the service. The
  filter returns `400` Problem Details on missing header
  (default) and rejects values longer than
  `platform.tenant.max-id-length=64`. The
  `AuditEvent` payload never carries a client-supplied
  tenant id; the value comes from the request header that
  the filter validated.
- Authorization/ABAC: N/A — no domain logic ships in this
  task; E3+ wires OpenFGA + ABAC. The
  `AuditEvent.resource` / `resourceId` fields are present
  so the ABAC layer can plug in without breaking changes.
- Secret/PII/DNA leakage: PASS — `application.yml`
  contains no literal credentials; the Spring datasource
  reads `SPRING_DATASOURCE_PASSWORD` from the environment
  (the value is empty in the YAML, so a missing secret
  fails startup). The OTel exporter endpoint is also env
  driven. The `AuditEvent` payload only carries opaque ids.
- Dependency/config scan: PASS — all new tooling is the
  same Apache-2.0 / MIT / MPL-2.0 stack already pinned in
  E1.1/E1.2/E1.3; no AGPL added on the SaaS control
  plane. `WireMock` and Testcontainers are test-only
  (Testcontainers is on the `testFixtures` classpath, not
  the production classpath).
- License discipline: PASS — see above.

## Residual risks

- The `com.google.protobuf` Gradle plugin is staged for
  E4. Two reasons: (1) the `genealogy/v1/person_service.proto`
  + `tree_service.proto` enums share value names
  (`PRIVATE` + `PUBLIC` in `Visibility`), and
  `protoc` treats the C++ scoping as a hard error;
  (2) the cross-service `tree_service.proto` imports
  `tenant_service.proto` which makes the contracts tree
  fragile. E4 will prefix enum values
  (`TENANT_STATUS_ACTIVE`, `MEMBERSHIP_STATUS_ACTIVE`, …)
  and re-enable the `protobuf {}` block. The shared
  `TenantService` gRPC implementation lands in E3.2
  once codegen runs.
- The `KeycloakFixture` does not import a realm yet — E3.1
  wires the config-as-code realm import per ADR-E0.5-05.
  For E1.4 the integration test uses a stubbed Keycloak
  JWKS via WireMock so the Spring Boot JWT decoder can
  start.
- The `OpenFeatureAutoConfiguration` only ships the
  `NoOpProvider` safe fallback. A real Flagsmith provider
  lands in E2.8 (per ADR-E0.5-13 the SDK stays
  provider-neutral so the swap is one line).
- The `integrationTest` source set requires Docker. CI
  runs both `test` and `integrationTest`; developers
  without Docker opt out with `-Dskip.it=true`. The
  `checkstyleIntegrationTest` task follows the same flag.
