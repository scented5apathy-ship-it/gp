## Decisions

- 13 fault classes cover the failure modes from the E13.4 requirement set (pod kill / network latency / Kafka lag / Temporal restart / OpenFGA outage / DB failover / OTel Collector down / DNS failure / clock skew / CPU pressure / memory pressure / disk pressure / TLS rotation). Each scenario file ships in `tools/chaos/scenarios/`.
- Retry budget: maxAttempts ≤ 6, maxWallSeconds ≤ 60. Manual retry / unbounded retry is FORBIDDEN.
- Circuit breaker: threshold 5, openSeconds 30, halfOpenProbeMax 1. The runtime library MUST instantiate a CB with these parameters whenever it wraps an outbound dependency.
- Graceful degradation: 8 critical dependencies × 4 modes (fail_closed / fail_open / read_only / cached) per the matrix. Postgres uses `cached` reads / `read_only` writes; OpenFGA + Vault + Kong use `fail_closed`; OTel Collector uses `fail_open`; Kafka uses `read_only` reads / `cached` writes; Temporal uses `fail_closed` reads / `cached` writes; S3 uses `cached` reads / `read_only` writes.
- Idempotency keys MUST be UUIDv7 + baseVersion + duplicateEventId forbidden. The runtime MUST NOT emit a Kafka event with the same eventId twice.
- Canary abort rules: 5xx > 1 % for 120s, p95 > 2× baseline for 180s, errorRate > 0.5 % for 180s, privacy finding ≥ 1 (immediate abort + budget freeze).
- Game day cadence: 90 days, 5 mandatory scenarios (pod_kill / db_failover / kafka_lag / openfga_outage / tls_rotation), 4 required artefacts (injects / observers / rollback / postmortem).
- Restore drill cadence: 90 days, 7 mandatory components (postgres / kafka / s3 / keycloak / openfga / temporal / vault), 5 required artefacts (dataset / RTO / RPO / restoreTooling / restoreEvidence).
- Tenant boundary MUST be respected under failure: no `tenant_id` ever appears in a degraded mode identifier.
