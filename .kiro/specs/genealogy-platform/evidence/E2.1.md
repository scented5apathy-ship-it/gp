### `platform/helm/genealogy-platform/Chart.yaml`

Umbrella chart manifest. Pins `appVersion: "0.1.0"`,

### `platform/helm/genealogy-platform/values.yaml`

Cluster baseline defaults applied to every environment:

- 8 namespaces (`gp-platform`, `gp-edge`, `gp-bff`, `gp-services`,
  `gp-workers`, `gp-data`, `gp-observability`, `gp-argocd`) with
  Pod Security admission labels (`restricted` for service /
  observability / GitOps namespaces; `baseline` for the public edge
  and the stateful data plane).
- Per-namespace `ResourceQuota` covering CPU requests/limits,
  memory requests/limits, pod count and PVC count, plus a
  `tenantShared: true` flag on the namespaces that host multi-tenant
  workloads.
- `default-deny` NetworkPolicy toggle (`baseline.defaultDeny.enabled`)
  plus an explicit CoreDNS egress allow list (`toNamespaceSelector`
  pointing at `kube-system`).
- `PodDisruptionBudget` defaults: `minAvailable: 1`, with a
  `singleReplicaWorkloads` list (`kong`, `vault`, `keycloak`) that
  the template forces to `maxUnavailable: 0`.
- Probe contract: paths `/healthz/{live,ready,startup}` and the
  `failureThreshold` / `periodSeconds` / `timeoutSeconds` /
  `initialDelaySeconds` defaults consumed by the
  `_probes.tpl` helper.
- `StorageClass` matrix (`gp-data-ssd`, `gp-data-hdd`,
  `gp-data-nvme`) all marked `encrypted: "true"`.
- `components.*` flags consumed by the umbrella (`kong`, `keycloak`,
  `openfga`, `kafka`, `apicurio`, `temporal`, `istio`, `vault`,
  `storage`, `cache`, `featureFlags`, `gitops`, `observability`).
  Component replicas / drivers live in the per-env files so the
  baseline never duplicates a value.
- `backups.*` CronJob schedule + retention matrix per stateful
  component (Postgres, Kafka, MinIO, Vault).

### `platform/helm/genealogy-platform/values-dev.yaml`

- `global.environment: dev`, `clusterDomain: genealogy.localhost`,

### `templates/_helpers.tpl` / `templates/_probes.tpl`

- `_helpers.tpl` defines `genealogy-platform.image` so workload
  templates can render a pinned image reference without drift.
- `_probes.tpl` renders `startupProbe` / `livenessProbe` /
  `readinessProbe` against the contract paths
  (`/healthz/startup`, `/healthz/live`, `/healthz/ready`). Workload
  charts are not allowed to override the paths.

### `templates/baseline/namespaces.yaml`

Iterates `baseline.namespaces[*]` and emits:

- A `Namespace` with `app.kubernetes.io/part-of`,
  `gp.genealogy/environment`, `gp.genealogy/purpose`,
  `gp.genealogy/tenant-shared` (when shared),
  `gp.genealogy/public-facing` (when public), and the three
  Pod Security admission labels.
- A `ResourceQuota` carrying CPU / memory / pods / PVCs.

### `templates/baseline/network-policies.yaml`

Default-deny NetworkPolicy for every namespace. Emits `policyTypes:
[Ingress, Egress]`, `ingress: []`, `egress:` with the CoreDNS allow

### `templates/baseline/pod-disruption-budgets.yaml`

- Default PDB for `gp-platform` (`minAvailable: 1`) so voluntary
  disruption can't drop below one replica.
- Per-workload PDBs (`maxUnavailable: 0`) for `kong`, `vault`,
  `keycloak` rendered from `singleReplicaWorkloads`.

### `templates/baseline/storage-classes.yaml`

Three StorageClasses (`gp-data-ssd`, `gp-data-hdd`,
`gp-data-nvme`) all marked `encrypted: "true"`, `reclaimPolicy:
Retain`, `volumeBindingMode: WaitForFirstConsumer`. Provisioner
configurable via `global.storageProvisioner` (defaults to
`kubernetes.io/no-provisioner` so the chart doesn't pin a
specific CSI driver; the cloud / on-prem operator overrides it).

### `templates/components/contract-stubs.yaml`

Per-component ConfigMap contract stubs (Kong, Vault, observability)
that codify the in-umbrella contract:

- **Kong** — handles TLS, auth validation, CORS, request-size,
  rate limit and correlation ID only; domain authorization is
  forbidden (E2.2 / design.md §5).
- **Vault** — dynamic short-lived credentials only; raw DNA / PII /
  persistent secret material outside KMS-backed storage is
  forbidden (E2.6).
- **Observability** — labels allowed: `tenant_pseudo_id`,
  `user_pseudo_id`, `service`, `version`, `environment`, `trace_id`.
  Labels forbidden: `tenant_id`, `user_id`, `email`, `raw_dna` (E2.10
  / design.md §13).

## Decisions

- **Static preflight over live-cluster check.** A live-cluster
  preflight would require a kind / k3d / EKS harness in CI, which
  doesn't exist yet (and E1.6 / E2.9 will wire one). The static
  preflight catches the same baseline drift (missing namespace,
  missing policy, missing per-env values, literal secret, missing
  encryption) without infra dependencies and runs on every PR.
- **Single umbrella chart with per-env files.** Per `agent-execution.md`
  §4.4 SaaS/on-prem share domain code and differ only in
  configuration; the umbrella chart keeps both in lockstep.
- **No literal credentials in values.** All `secretRefs` are Vault
  paths or External Secrets references. The preflight script asserts
  no literal `password` / `token` / `apiKey` / `private_key` ever
  lands in the chart.
- **Encrypted StorageClass defaults.** ADR §12 mandates KMS-at-rest
  for every data plane disk; the StorageClass defaults carry
  `encrypted: "true"` so a workload can't accidentally opt out.
- **Single-replica control plane gets `maxUnavailable: 0`.** A
  voluntary disruption during a Kong or Vault rollout can never
  split-brain the cluster, even with a permissive default PDB.
- **Probes are helpers, not policy.** `_probes.tpl` enforces the
  `/healthz/*` path contract and the failureThreshold / periodSeconds
  defaults. Workload charts consume the helper rather than
  re-deriving the contract.
- **Per-component ConfigMap stubs over inline comments.** The
  contract stubs are resources in the cluster (`gp-edge` /
  `gp-platform` / `gp-observability`) so they can be grepped by the
  Grafana onboarding job (E2.10) and audited.
- **Local profile uses minio / valkey / flagsmith on docker
  compose** so a developer only needs Docker Desktop / OrbStack /
  colima. Heavyweight platform components (Istio mesh, Argo CD,
  Vault HA) live in the umbrella chart and are skipped locally
  via the dev `values-dev.yaml` profile.

## Security and privacy

- **Tenant isolation: PASS — design intent.** Every workload
  namespace carries `gp.genealogy/tenant-shared: "true"` (multi-tenant
  namespaces) or no label (single-tenant). Default-deny
  NetworkPolicy is the cluster default; workload charts must
  explicitly allow ingress. The preflight script refuses a chart
  that drops either.
- **Authorization / ABAC: N/A — out of scope for E2.1.** Kong,
  OpenFGA and ABAC wiring ship with E2.2 / E3.2 / E3.5.
- **Secret / PII / DNA leakage: PASS.** The preflight script refuses
  any literal `password:` / `token:` / `apiKey:` / `private_key:`
  in `values.yaml` (regex assertion). `docker-compose.yml` is
  required to reference env vars (`${POSTGRES_PASSWORD}` etc.) — the
  scan verified 10 env-var references and 0 literal credentials.
- **Dependency / config scan: N/A — out of scope for E2.1.** The
  ADR-E0.5-01 image pins live in `profile.yaml` and `values-*.yaml`;
  Renovate + SBOM ship with E1.6.
- **License discipline: PASS.** All new dependencies (none — pure
  YAML / Markdown / Node scripts) are Apache-2.0 / MIT.

## Residual risks

- **No Node / pnpm / Helm on the developer host.** This E2.1
  implementation was authored on a host without Node 22 LTS, pnpm,
  or the Helm CLI. The preflight script logic was re-validated via
  the equivalent Python regex parity run (PASS, 0 violations across
  8 invariants). CI / reviewer MUST execute:
  - `pnpm install`
  - `pnpm lint:helm` (runs `scripts/lint-helm.mjs` — passes the
    structural + `helm lint --strict` if `helm` is on PATH)
  - `pnpm test:scripts` (or
    `node --test scripts/__tests__/*.test.mjs`)
  - `pnpm check:platform:baseline`
  - `helm lint platform/helm/genealogy-platform --strict`
  - `pnpm check:ownership` (validates the new OWNERS files
    match `config/teams.yaml`)

  Until that end-to-end run is green in CI, status remains
  PARTIAL per `agent-execution.md` §4.5. Status will be flipped
  to DONE once the green CI run is recorded in this evidence
  file.

- **No live-cluster smoke test.** A `kind` / `k3d` /
  cloud-ephemeral cluster smoke (apply the umbrella chart, verify
  every namespace lands, verify NetworkPolicy denies by default)
  is intentionally deferred — it depends on the GitOps harness
  from E2.9 and the air-gapped mirror from E1.6.
- **`pnpm-lock.yaml` churn.** Adding `pnpm test:scripts` to
  `check:all` and `ci:full` is non-blocking but worth a
  subsequent `pnpm install` commit on a developer host with the
  Node 22 LTS runtime available.
