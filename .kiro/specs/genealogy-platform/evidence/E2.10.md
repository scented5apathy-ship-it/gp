## Decisions

- **ADR-E0.5-01 baseline pin** (image versions per the
  ADR table): OTel Collector `0.110.0`, Prometheus
  `v2.55.0`, Loki `3.4.0`, Tempo `2.7.0`, Grafana
  `11.3.0`. No literal version inside any service
  `build.gradle.kts`; the umbrella chart is the single
  source.
- **Single-tenant Loki + Tempo** (matches Grafana Cloud /
  ADR-E0.5-01 baseline). Per-tenant isolation is NOT a
  Loki/Tempo concern — the data plane enforces it via
  `tenant_pseudo_id` hash bucketing + Postgres RLS + Kong
  routing. The OTel Collector is the **single ingress**
  for all 11 services + 5 workers + 6 platform components.
- **PII / DNA / OIDC redaction** at the OTel Collector
  `redaction` processor (9 regex rules covering SSN,
  passport, driver-license, email, phone, ipv4, JWT, raw
  DNA marker `rs\d{2,8} [ACGT]{2}`, Authorization header).
  Loki + Tempo + Prometheus enforce `deny_labels` as a
  second-line defense. `filter/logs` drops records with
  `raw_dna|raw_pii|consent_dropped|legal_hold_pii` body.
- **Tenant pseudonym** via HMAC-SHA256 keyed by Vault-managed
  pepper (`tenant_pseudo_id` / `user_pseudo_id` /
  `actor_pseudo_id`). Raw `tenant_id` / `user_id` / `email` /
  `oidc_subject` / `raw_dna` / `raw_pii` are FORBIDDEN at
  every exporter boundary.
- **Audit pipeline** is the dedicated `otlp/audit` receiver
  (port 4319) → `attributes/tenant-pseudonym` →
  `transform` (drop raw labels) → `redaction` →
  `resource/audit` (force `actor_pseudo_id`) → `otlp/audit`
  exporter. The deep linter enforces raw `email` /
  `oidc_subject` cannot survive the pipeline.
- **9 mandatory dashboards**: api-overview / kong / kafka /
  temporal / openfga / istio / vault / database / workload
  (per `tasks.md` E2.10). Template variables MUST use
  `tenant_pseudo_id` only; `templateVariablesForbidden`
  blocks `tenant_id` / `user_id` / `email` / `oidc_subject`
  / `raw_dna` / `raw_pii`.
- **Retention per-env** (dev / on-prem / saas): 7d/30d/90d
  Prometheus, 7d/30d/90d Loki, 3d/14d/30d Tempo. The
  umbrella chart enforces the retention via
  `--storage.tsdb.retention.time` + Loki compactor +
  Tempo `block_retention`.
- **Reuse upstream** (do NOT build a custom metric
  backend / log aggregator / trace storage / dashboard
  UI): `otel/opentelemetry-collector-contrib`,
  `prom/prometheus`, `grafana/loki`, `grafana/tempo`,
  `grafana/grafana`. Per AGENTS.md §5 we never invent a
  platform capability these upstreams already provide.

## Security and privacy

- **Tenant isolation**: PASS — `tenant_pseudo_id` (HMAC-SHA256)
  is the only tenant identity emitted by the OTel
  Collector / Loki / Tempo / Prometheus. Raw `tenant_id`
  is rejected at every exporter boundary.
- **Authorization/ABAC**: N/A — Grafana access is gated by
  Keycloak OIDC SSO + 2FA conditional flow; ABAC overlays
  (living / DNA / consent) are service-owned per
  `ownership-catalog.md`.
- **Secret/PII/DNA leakage**: PASS — the OTel Collector
  `redaction` processor scrubs 9 categories (SSN /
  passport / driver-license / email / phone / ipv4 / JWT /
  raw DNA marker / Authorization header) before any
  exporter writes. `transform` + `filter/logs` drop raw
  identity labels at the metric / log layer. Loki +
  Tempo + Prometheus enforce `deny_labels` as a second
  line of defense.
- **Dependency/config scan**: PASS — image pins are
  ADR-E0.5-01 baseline (latest stable); Renovate bumps
  per the policy. No literal secret / token / pepper /
  API key in any file.
