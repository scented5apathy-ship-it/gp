## Changes

### `platform/helm/genealogy-platform/files/kong.yml`

Canonical Kong declarative config (Kong 3.x, DB-less). One file is
the source of truth for SaaS / on-prem / local; the Helm chart
mounts it via the `kong-declarative-config` ConfigMap and the local
docker-compose mounts it at `/etc/kong/kong.yml`
(`platform/kong/kong.yml` is a symlink to this file).

- 4 services: `web-public`, `web-bff`, `public-api`, `admin-api`
  pointing to `gp-bff` / `gp-platform` namespaces respectively.
- 4 routes — every route carries a `route-class:<name>` tag so a
  config drift is grep-able from CI logs:
  - `public-web-root` → `web-public` (`route-class:public`)
  - `web-bff-api`     → `web-bff`    (`route-class:authenticated`)
  - `public-api-v1`   → `public-api` (`route-class:partner`)
  - `admin-api-v1`    → `admin-api`  (`route-class:admin`)
- 14 plugins (per route, not global):
  - `correlation-id` — every route, generates an `X-Request-Id` UUID
    and echoes it downstream for trace propagation across CDN → BFF
    → gRPC.
  - `cors` — `public-web-root` + `web-bff-api` only; partner/admin
    are server-to-server and intentionally reject browser origins.
  - `request-size-limiting` — `web-bff-api` (16 MB), `public-api-v1`
    (8 MB), `admin-api-v1` (4 MB).
  - `rate-limiting` — every route, coarse edge limit (`local` policy
    so it survives a Valkey outage; per-route thresholds 60–600 / min).
  - `ip-restriction` — `admin-api-v1` only (bastion + Argo CD +
    on-call VPN).
  - `jwt` — slot reserved for E3.1; no `key_claim_name` resolved
    today (lint script enforces this).
- Domain-authorization plugins (`oauth2-introspection`, `mtls-auth`,
  `key-auth`, `acl`, `basic-auth`, `ldap-auth`) are forbidden by the
  linter. The `kong-contract-stub` ConfigMap encodes the same
  responsibilities + forbidden list.

## Decisions

- **DB-less declarative config in git.** Kong runs without a Postgres
  / Cassandra backend so route / plugin changes ship as Helm
  revisions and the Kong admin API is never reachable from the
  cluster network (`KONG_ADMIN_LISTEN=127.0.0.1:8444`). Rollback =
  `helm rollback`.
- **One declarative config for every environment.** The chart's
  `files/kong.yml` is the single source of truth; SaaS / on-prem /
  dev wire it through different values (replicas, resources,
  Service hosts) but the route + plugin diffs stay in one file.
- **Routes are path-scoped and SNI-scoped.** Every route declares a
  narrow path prefix + a single SNI, so a cross-route request
  cannot reach the wrong backend.
- **Plugins are route-scoped, not global.** Per `design.md` §13 we
  avoid the global plugin block so the diff is auditable.
- **`KONG_PLUGINS` allow-list at startup.** Anything outside
  `bundled + 7 named plugins` is denied so a developer cannot
  accidentally load `oauth2-introspection`, `mtls-auth`, `key-auth`
  or `acl` — domain authorization is a service-side concern per
  `design.md` §4.1.
- **JWT plugin is a reserved slot.** E3.1 wires the Keycloak key
  resolver + claims mapping; today the plugin is enabled but the
  linter rejects any `key_claim_name` so Kong never resolves an
  OIDC principal.
- **`ip-restriction` on the admin route only.** A platform bastion
  + Argo CD + on-call VPN allow-list is the bare minimum; full
  per-route authorization remains in `tenant-service`.
- **Symlinked `platform/kong/kong.yml`.** Helm's `.Files.Get`
  resolves paths relative to the chart root, so the canonical file
  lives at `platform/helm/genealogy-platform/files/kong.yml`. The
  docker-compose mounts the same source via a symlink so there is
  no risk of drift.
- **No Kong admin REST exposure.** `KONG_ADMIN_LISTEN` binds to
  `127.0.0.1:8444` so the admin API is unreachable from the
  cluster. The Helm Deployment does not declare an admin Service
  or admin NetworkPolicy ingress.
- **No Kong Enterprise license dependency.** Per ADR-E0.5-04 the
  runtime is Kong OSS 3.8 (Apache-2.0). Built-in WAF, RBAC for
  admin and the developer portal are explicitly out of scope.

## Security and privacy

- **Tenant isolation: PASS — design intent.** The four route classes
  are path-scoped, SNI-scoped and tag-scoped so a request cannot
  reach the wrong backend. `ip-restriction` blocks off-bastion
  traffic to the admin route. Default-deny NetworkPolicy baseline is
  layered on top by `templates/baseline/network-policies.yaml`.
- **Authorization / ABAC: PASS — boundary enforced.** Kong handles
  JWT verification (slot reserved for E3.1) but **never** resolves
  an OIDC principal. Domain authorization (`oauth2-introspection`,
  `mtls-auth`, `key-auth`, `acl`, `basic-auth`, `ldap-auth`) is
  forbidden by the linter; OpenFGA + ABAC stays in the destination
  service per `design.md` §4.1.
- **Secret / PII / DNA leakage: PASS.** No literal credentials in
  `kong.yml` or `values.yaml` (linted by
  `lint-kong-config.mjs`). Kong TLS is provisioned from cert-manager
  via External Secrets; the chart's Kong Secret reference is named,
  not inlined.
- **Dependency / config scan: N/A — out of scope for E2.2.** Kong
  OSS 3.8 is Apache-2.0; Renovate + Trivy ship with E1.6.
- **License discipline: PASS.** Kong OSS + `yaml` devDep
  (Apache-2.0 / MIT). No AGPL dependency introduced.
