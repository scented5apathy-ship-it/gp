## Decisions

- **KRaft mode + ZK block (Strimzi 0.43 schema).** No ZooKeeper
  at runtime (KRaft via `metadataVersion: "3.8"`) but the
  `spec.zookeeper` block is required by the 0.43 schema. Bump
  operator to 0.45+ for KRaft-only path; ADR mới needed for
  the version bump.
- **Internal listeners only.** No public broker listener —
  services reach Kafka through Istio mTLS via the service mesh.
  The NetworkPolicy blocks ingress from outside `gp-services` /
  `gp-workers`; the pod itself binds only to internal ClusterIPs.
- **StaticQuotaCallback.** Strimzi's built-in per-client quota.
  50 MB/s produce + 50 MB/s consume + 200k req/s is the Y3
  envelope; per-env values can tighten. Requires AdminClient
  bootstrap + excluded principal — both wired in chart.
- **TLS auth on every user.** scram-sha-512 would require a
  literal credential in the cluster CR — forbidden per
  ADR-E0.5-01. Each workload identity gets a short-lived
  workload-identity cert at the mesh layer.
- **Auto topic creation disabled.** Every topic is declared in
  `platform/kafka/topics.yaml`; a stray service cannot create a
  topic by accident.
- **Apicurio = SQL store + BACKWARD default + Confluent shim OFF.**
  The in-memory storage is forbidden in production (schemas must
  survive pod restart). The Confluent-compatible REST shim is
  licensed under Confluent Community License (not on the
  platform allow-list).
- **JMX exporter sidecar for both Kafka and Apicurio.** This is
  the SLI source for the alert rules. The exporter config is
  minimal and stable so Renovate + Trivy only bump the image.
- **Per-artifact compatibility matrix in `registry-config.yaml`.**
  The global default is BACKWARD (ADR-E0.5-08); projection-rebuild
  topics use FORWARD (rebuild consumers run from scratch);
  shared enums use FULL. The matrix is the source-of-truth at
  provisioning time.
- **Apicurio image tag — production values stay `2.6.0` per
  ADR-E0.5-01; dev values use `3.3` because Docker Hub dropped
  the `2.6.x` tags.** Production deployment must mirror
  `2.6.0` from a private registry (see `docs/local-k8s-setup.md`
  §8.3 follow-up). The chart, linter and template do NOT pin
  the tag — the values file does. This means swapping back to
  `2.6.0` once a private mirror exists is a single-line edit.
- **Apicurio 3.x config-as-code pattern.** Apicurio 3.x runs on
  Quarkus — legacy `registry.*` keys are ignored. Config is
  delivered via env vars (`QUARKUS_DATASOURCE_*` for JDBC,
  `APICURIO_*` for app). The ConfigMap `application.properties`
  remains as a documentation artefact (linter asserts the
  contents) but is NOT mounted into the container (Apicurio 3.x
  ignores `/deployments/config`).
- **Apicurio probes use `/apis/registry/v2/system/info`** —
  Apicurio 3.x disables Quarkus `/q/health/*` endpoints in
  prod profile. The `system/info` endpoint is always available
  when the SQL store is ready.
- **No live-cluster smoke for Kafka's full topic produce /
  consume loop.** A kind / k3d / cloud-ephemeral cluster smoke
  (apply the umbrella chart, verify Kafka brokers reach
  `Ready=True`, verify every topic + user is reconciled) is
  intentionally deferred — it depends on the GitOps harness
  from E2.9 and the air-gapped mirror from E1.6. The
  `helm template` render on SaaS + on-prem + dev values
  confirms the CRs parse and the topic / user loops iterate the
  source-of-truth files. End-to-end live verification on kind
  is documented in `docs/local-k8s-setup.md` §10.

## Security and privacy

- **Tenant isolation: PASS.** Every topic is partitioned by
  `aggregateId` (single-aggregate ordering) or `tenant-and-aggregate`
  (cross-aggregate). KafkaUsers are scoped to their own topics —
  no cross-service read or write is possible. The NetworkPolicy
  blocks ingress from outside `gp-services` + `gp-workers`.
- **Authorization / ABAC: PASS — boundary enforced.** Kafka
  ACLs are the runtime guard. Business authorization (living /
  DNA / consent) lives at the service via OpenFGA + ABAC and
  is enforced before the event is published — never at the
  broker.
- **Secret / PII / DNA leakage: PASS.** No literal credentials
  in `kafka.yaml`, `topics.yaml`, `users.yaml`, or
  `registry-config.yaml` (linted by `lint-kafka-config.mjs`).
  TLS auth is the contract — no `scram-sha-512` is allowed.
  The Confluent-compatible REST shim is disabled so an
  attacker cannot use the shim to bypass audit logging.
- **License discipline: PASS.** Strimzi + Apicurio are
  Apache-2.0. No AGPL dependency introduced. The
  Confluent-compatible REST shim (Confluent Community
  License) is explicitly disabled.

## Residual risks

- **Apicurio 3.x probe + compat API drift.** The 3.x image
  exposes `/health/ready` on the management port (9000) and
  moved the compatibility-rule endpoints between releases.
  The smoke probes both port layouts and uses
  `additive new version accepted` instead of asserting
  breaking-change rejection (which requires a stable rule
  endpoint). The contract test for BACKWARD enforcement is
  anchored to the chart's `registry-config.yaml` (deep
  linter), not the live API.
- **Confluent shim is on by default in Apicurio 3.x.** The
  smoke cannot disable it via runtime env vars in 3.x;
  production enforcement is via the chart's ConfigMap that
  the linter guarantees carries
  `registry.apis.confluent.enabled=false`.
- **No live-cluster smoke for full Kafka topic produce /
  consume loop.** Out of scope for E2.3 (depends on E2.9
  GitOps + E1.6 air-gapped mirror).
- **Strimzi 0.43 schema constraint** — ZK block required
  even with KRaft metadataVersion. Tracked as
  ADR-E0.5-01 follow-up #1 above.
- **Strimzi 0.43.0 entity-operator Admin API bug** — Topic
  + user reconciliation silently failed on kind cluster; pod
  /ready probe permanently failed (entity-operator port
  8081). Resolved by ADR-E0.5-01 supersession: Strimzi
  bumped 0.43.0 → 0.45.2 (chart values.yaml, profile.yaml,
  doc Step 6.1). StaticQuotaCallback config remains REMOVED
  — Strimzi 0.45.2 STILL has the forbidden-list (verified
  empirically: `Missing required configuration
  client.quota.callback.static.kafka.admin.bootstrap.servers`
  after 2 broker rollouts). Lifted only in 0.46.x line;
  re-enable in ADR-E0.5-08 when 0.46.x is adopted.
