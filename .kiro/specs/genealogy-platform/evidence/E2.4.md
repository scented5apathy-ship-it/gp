## Decisions

- **Self-hosted Temporal everywhere (ADR-E0.5-07).** The chart
  renders the all-in-one `temporal-server` StatefulSet (front-end
  + history + matching + worker on distinct ports, same binary
  the upstream `temporalio/temporal` Helm chart uses). SaaS may
  swap to Temporal Cloud only with an explicit ADR that documents
  in-region + on-prem parity — tracked separately.
- **PostgreSQL persistence on `gp-data`.** Temporal history lives
  in the chart's PostgreSQL cluster (`genea_temporal` database +
  `temporal-postgres-credentials` secret). The Helm pre-install
  hook from E2.1 provisions the database + role; the chart only
  references the secret.
- **Search attribute whitelist = 9 opaque IDs only.** No raw PII,
  DNA, token, file content, signed URL, or Keycloak subject.
  Workers pseudonymize via the platform `tenant-pseudo-id`
  library before `UpsertWorkflowExecutionOptions`. The
  `dynamic-config.yaml` `system.visibility.attribute` block carries
  the whitelist server-side; the worker SDK template enforces it
  client-side.
- **DNA namespace = 365-day retention per
  `privacy-and-legal-gate.md` §14.** Revocation evidence must
  survive the longest legal hold window the platform supports at
  GA. Bump only via ADR.
- **Helm-hook Jobs for namespace + task-queue reconciliation.**
  Two Jobs (`temporal-namespace-init`, `temporal-task-queue-init`)
  re-emit `temporal operator namespace` /
  `temporal task-queue update` for every entry in
  `namespace-config.yaml` / `task-queues.yaml` on every `helm
  upgrade`. The Jobs run before the StatefulSet rolls and delete
  themselves on success.
- **UI is restricted to `gp-platform` + `gp-observability`.** No
  public ingress. Operators reach the UI via the platform
  SSO-protected BFF route (E3.5) before opening the public edge.
- **Worker identity = Kubernetes service-account name.** The
  `task-queues.yaml` allowlist enforces this; any unknown
  identity is rejected at `RegisterTaskQueue`. Workers register
  via the Istio-mTLS-secured gRPC channel.
- **Default 24-hour workflow execution timeout.** Matches ADR-E0.5-07
  (a saga must not exceed a single operator shift). Activities
  default to 60s `scheduleToCloseTimeout` + 10s `heartbeatTimeout`
  + 3 retry attempts with 1s/30s/2.0x exponential backoff. Domain
  services override per activity if needed.
- **In-memory scratch volume only.** The StatefulSet reserves a
  small `data` PVC (10Gi default) for local caches; history state
  lives in PostgreSQL so the volume is intentionally small. The
  per-env values file picks the storage class (`standard` on dev,
  `gp-data-ssd` on SaaS / on-prem).

## Security and privacy

- **Tenant isolation: N/A at the Temporal layer.** Temporal is a
  workflow engine, not a tenant-aware data store; tenant
  isolation is enforced at the domain service via OpenFGA + ABAC
  (the Temporal worker SDK never persists tenant data outside
  workflow execution history). The `tenant_id` predicate on every
  workflow input is the worker's responsibility.
- **Authorization / ABAC: PASS — boundary enforced.** Search
  attributes are opaque IDs only; the worker SDK validates the
  whitelist before sending. Business authorization (living /
  DNA / consent) is at the service via OpenFGA + ABAC; Temporal
  does NOT carry business policy.
- **Secret / PII / DNA leakage: PASS.** No literal credentials in
  any of the four source-of-truth files (linted by
  `lint-temporal-config.mjs`). The PostgreSQL connection reads
  from the `temporal-postgres-credentials` secret via the
  `secretKeyRef` mount in the StatefulSet.
- **License discipline: PASS.** Temporal is Apache-2.0 (server,
  UI, admin-tools). No AGPL dependency introduced.

## Residual risks

- **Smoke probe depends on Docker on PATH + `host.docker.internal`
  not required.** The probe uses the `gp-smoke` user-defined
  network so the Temporal container resolves the PostgreSQL
  container by name (`gp-pg-smoke`). The probe also pulls the
  `temporalio/admin-tools` image on first run (~50 MiB). CI
  caches should pre-pull it.
- **`temporal` admin-tools image entrypoint.** The
  `temporalio/admin-tools` image's default `temporal` entrypoint
  is the system worker (hangs); the smoke probe invokes `tctl`
  directly via `--entrypoint /bin/sh -c "tctl ..."`. The chart's
  Helm-hook Jobs use the same `tctl`-via-`sh` pattern.
- **No live-cluster smoke on kind.** Same constraint as E2.3
  (depends on E2.9 GitOps + E1.6 air-gapped mirror). The
  `helm template` render on SaaS + on-prem + dev values confirms
  the chart parses and all the templates render. End-to-end
  live verification on kind is documented in
  `docs/local-k8s-setup.md` (out of scope for E2.4).
- **In-memory scratch volume size.** The StatefulSet reserves
  10Gi (default) / 2-50Gi (per-env). The chart does NOT enforce
  capacity bounds at runtime — operators should size the volume
  against the per-env expected cache load (out of scope for
  E2.4; tracked in E13.3 capacity).
