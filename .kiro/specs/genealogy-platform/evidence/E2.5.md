## Decisions

- **STRICT mTLS by default + DENY by default.** Per the E2.5
  contract, every workload namespace pins STRICT mTLS via a
  per-namespace PeerAuthentication CR (`platform/istio/peer-auth.yaml`).
  The mesh-wide default in `gp-platform` is the safety net for
  any namespace that does not declare its own CR. The MeshConfig
  also pins `inboundPolicy: MUTUAL_TLS` so the proxy rejects
  plaintext traffic even before the PeerAuthentication is
  evaluated.
- **REGISTRY_ONLY outbound + dedicated DENY for dna /
  media workers.** Per `ownership-catalog.md` §3 the dna-service
  and media-worker isolation is enforced by E10.2 + E7.2. The
  AuthorizationPolicy CRDs add the mesh-level deny: dna-service
  is the only identity that may reach the DNA PostgreSQL
  database or the `dna-raw` object prefix; media-worker egress
  is denied to the public internet (only the ClamAV / Tika /
  FFmpeg / Gotenberg sandbox pods are reachable).
- **No mesh-level retry.** Per `design.md` §13 the mesh and
  application retry budgets are kept disjoint. The mesh has
  `retryBudget: null`; the application retries at 3 attempts
  with `50ms / 2s / 2x` backoff. The cumulative retry fan-out
  stays ≤ 9 (3 app × 1 mesh), well under the 12-attempt budget
  the on-call workbook mandates for cascade failures (E13.4).
- **OTel trace driver + JSON access log.** The OTel Collector
  sidecar (E2.10) is the canonical source of truth for trace
  export; the Zipkin driver in `mesh-config.yaml` is left blank
  intentionally. The JSON access log includes the SPIFFE
  principal so the OTel log pipeline can redact PII / DNA per
  `privacy-and-legal-gate.md` §11.
- **Helm-hook Job for bootstrap.** The `istio-bootstrap` Job
  runs on every `helm upgrade` (`pre-install,pre-upgrade`) and
  applies the four source-of-truth ConfigMap-derived manifests
  via `kubectl apply --server-side`. The Job uses the
  `bitnami/kubectl:1.31.1` image (small, includes `python3`)
  so it does NOT require the heavy `istioctl` binary in the
  Job container.
- **Trust domain = `cluster.local`.** Pinned to the
  `global.clusterDomain` default. The trust domain is
  overridable per deploy via `--set global.clusterDomain` for
  multi-cluster topologies (ADR-E0.5-03 supersession tracks
  the cross-region trust domain naming).

## Security and privacy

- **Tenant isolation: N/A at the Istio layer.** Tenant isolation
  is enforced at the domain service via OpenFGA + ABAC
  (`privacy-and-legal-gate.md` §6). The Istio mesh gates
  network-level authorization (workload identity + namespace);
  it never carries tenant data on the wire.
- **Authorization / ABAC: PASS — boundary enforced.** The
  AuthorizationPolicy CRDs deny traffic from forged principals
  (any SPIFFE ID not on the allow-list). Business authorization
  (living / DNA / consent) is at the service via OpenFGA + ABAC;
  Istio does NOT carry business policy.
- **mTLS / STRICT posture: PASS.** Every workload namespace
  pins STRICT mTLS via PeerAuthentication. The MeshConfig
  enforces `inboundPolicy: MUTUAL_TLS`; the per-namespace CRs
  enforce STRICT; the linter rejects `PERMISSIVE` / `DISABLE`.
- **Secret / PII / DNA leakage: PASS.** No literal credentials
  in any of the four source-of-truth files (linted by
  `lint-istio-config.mjs`). The bootstrap Job reads from the
  ServiceAccount's projected token.
- **DNA service + media worker isolation: PASS.** The
  AuthorizationPolicy CRDs deny traffic to the dna-service from
  any identity that is not `dna-service` or `dna-worker`. The
  media-worker is denied access to the public internet.
- **License discipline: PASS.** Istio is Apache-2.0; the
  bootstrap Job uses `bitnami/kubectl` (Apache-2.0). No AGPL
  dependency introduced.

## ADR / follow-up items

- **ADR-E0.5-03 follow-up (already in design):** region-aware
  trust domain for cross-region failover. Until ADR-E0.5-03
  closes, the trust domain is `cluster.local`; the cross-region
  trust domain is appended to the cluster domain (e.g.
  `cluster.local.eu-central-1`).
- **ADR new (E2.5.x):** ambient mode rollout. The MeshConfig
  declares `ISTIO_META_ENABLE_HBONE: "true"` (required by
  Istio 1.23.x ambient mode) but the chart still ships the
  sidecar-injection default. The ambient mode rollout is
  tracked separately once the E2.5 quality gates close.
- **ADR new (E2.5.x):** AuthorizationPolicy authoring
  experience. The `authz-policies.yaml` source-of-truth is
  hand-authored; an `authz-codegen` tool that derives the
  allow rules from the platform's `services/<svc>/OWNERS`
  + the `ownership-catalog.md` RACI is out of scope for E2.5
  but tracked for E3.5 (trusted tenant context).

  script falls through to a structural-only 5/5 PASS when those
  are unavailable. CI runs on a disposable kind cluster per
  `docs/local-k8s-setup.md` (out of scope for E2.5; same

- **Bootstrap Job image pin.** `bitnami/kubectl:1.31.1` is
  pinned for reproducibility; the Renovate policy bumps the
  patch line per ADR-E0.5-01.
- **No live-cluster smoke on kind.** Same constraint as E2.3 /
  E2.4 (depends on E2.9 GitOps + E1.6 air-gapped mirror). The
  `helm template` + `lint-istio` + `smoke-istio` (structural)
  assertions confirm the files are correct. End-to-end live
  verification on kind is documented in
  `docs/local-k8s-setup.md` (out of scope for E2.5).
- **AuthorizationPolicy source-of-truth is hand-authored.** The
  `authz-policies.yaml` is hand-edited; a future ADR
  (E2.5.x follow-up) introduces an `authz-codegen` tool that
  derives the allow rules from the platform `OWNERS` catalog.
