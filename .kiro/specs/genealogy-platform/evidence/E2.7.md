## Decisions

- **Provider-neutral application contract.** Domain code
  binds to `com.genealogy.platform.storage.ObjectStorageProvider`
  (S3) and `com.genealogy.platform.cache.CacheClient`
  (Valkey); the runtime provider is selected by the per-env
  `storage.provider` + `cache.provider` value. Domain code
  never branches on the provider.
- **AWS S3 for SaaS, MinIO for on-prem + dev.** Per
  `tasks.md` E2.7 + `design.md` §13 + ADR-E0.5-03, SaaS
  uses managed AWS S3; on-prem uses self-hosted MinIO. The
  chart's MinIO workload is bypassed on SaaS via
  `provider: aws-s3`; the same bucket policy file is shipped
  to the AWS account via the IaC pipeline.
- **No public READ ACL on `media` bucket.** Delivery always
  goes through BFF + ABAC (E3.4); the bucket NEVER carries
  a public ACL. The bootstrap Job applies
  `mc anonymous set none` on every bucket.
- **`dna-raw` isolated bucket (E10.2).** The web-bff has
  NO IAM binding to `dna-raw`; only `dna-service` +
  `dna-raw` worker may write. Object lock COMPLIANCE mode
  + 7-year retention. The bucket prefix never carries raw
  subject_id.
- **Object lock COMPLIANCE mode on `dna-raw` +
  `import-export`.** Compliance mode prevents even the
  root account from deleting objects before retention
  expires. E10.5 consent revocation is the only path to
  legal delete.
- **Signed URL TTL ceiling 1 hour; export bucket 15 min.**
  Application code MUST NOT generate signed URLs with
  TTL > 1 hour; the export bucket overrides to 15 min
  per E9.4 privacy-aware export.
- **Valkey is NEVER source of truth.** Cache data is
  fail-safe only; domain services rebuild cache state
  from PostgreSQL on Valkey restart. Per `design.md`
  §3.1 + `scale-and-slo.md` §10, the cache hit ratio
  target is ≥ 85%; a hit ratio < 50% is an incident.
- **`@admin` ACL reserved for the `operator` user.**
  Service users MUST NOT carry `@admin`. The deep
  linter rejects `@admin` on any non-operator user.
- **`maxmemoryPolicy: allkeys-lru` only.** `noeviction`
  is forbidden (silent OOM risk).
- **Per-class TTL ceilings.** The deep linter enforces
  `ttl.X` ≤ `ttl.XCeiling` for every class. A leaking
  OpenFGA / ABAC cache (E3.4) is the canonical cause
  of memory pressure; the per-class ceiling catches it.
- **Cross-provider compatibility test.** Per `tasks.md`
  E2.7 ("Chạy compatibility tests giữa cloud S3 và
  MinIO"), `scripts/check-s3-compatibility.mjs` asserts
  23 required S3 operations + 7 parity invariants + 5
  forbidden patterns. The test harness is
  Testcontainers (MinIO) + aws-sdk-client-mock (AWS S3);
  CI runs the unit mock; integration runs the live
  Testcontainer.

## Security and privacy

- **Tenant isolation: PASS.** Every bucket prefix template
  includes `{tenant_pseudo_id}`; the linter rejects raw
  `tenant_id=` / `person_id=` / `user_id=` /
  `raw_dna/` prefixes. Valkey key namespace is
  `gp:{tenant_pseudo_id}:*`; the linter rejects keys
  outside this namespace.
- **Authorization / ABAC: PASS — boundary enforced.**
  S3 / Valkey decide credential scope only. Domain
  authorization (living / DNA / consent) stays in the
  destination service via OpenFGA + ABAC; the contract
  stub explicitly forbids business authorization in
  S3 / Valkey. The `dna-raw` bucket is E10.2 isolated
  (separate IAM, separate KMS key, separate
  NetworkPolicy).
- **Secret / PII / DNA leakage: PASS.** The deep linter
  rejects literal `password`, `apiKey`, `token`,
  `private_key`, `AWS_ACCESS_KEY_ID`,
  `AWS_SECRET_ACCESS_KEY` values. No raw DNA / PII /
  secret payload is stored in Git / Helm values /
  image / logs / Temporal payload. The Valkey forbidden
  key patterns forbid `*raw_dna*`, `*password*`,
  `*apiKey*`, `*token*`, `*private_key*`, `*ssn*`,
  `*credit_card*`.
- **Encryption: PASS.** SSE-KMS on every bucket via the
  bucket-specific KMS key alias
  (`alias/genea-s3-media-derivative`,
  `alias/genea-s3-genetic-raw`,
  `alias/genea-s3-secret`); Valkey TLS 1.2 minimum
  with cert-manager-managed cert.
- **Object lock: PASS.** `dna-raw` bucket uses COMPLIANCE
  mode with 7-year retention; `import-export` bucket uses
  COMPLIANCE mode with 30-day retention. E10.5 consent
  revocation is the only legal delete path.
- **Signed URL TTL: PASS.** Default ceiling 1 hour;
  export bucket override 15 min. The
  `S3SignedUrlTtlViolation` alert fires on any violation.
- **Default deny: PASS.** NetworkPolicy denies Ingress
  + Egress by default; allow rules are namespace-scoped
  + port-scoped. The `media` console is reachable only
  from the bastion VPN.
- **License discipline: PASS.** MinIO is Apache-2.0;
  Valkey is BSD-3-Clause; Valkey exporter is MIT; MC is
  Apache-2.0. No AGPL dependency introduced.

## Residual risks

- **Live-cluster smoke depends on kind + kubectl + helm
  on PATH.** The script falls through to structural-only
  4/4 PASS when those binaries are unavailable. CI runs
  the full live smoke on the disposable kind cluster
  documented in `docs/platform-setup.md`.
- **6 pre-existing platform baseline failures.**
  `pnpm check:platform:baseline` still reports the six
  pre-existing missing `platform/local/{keycloak,openfga,
  kafka,storage,cache,flags}` entries. These failures
  pre-date E2.7 and are already documented in
  `evidence/E2.5.md` + `evidence/E2.6.md`; no E2.7 /
  storage / cache invariant fails.
- **AWS provider remains provider-neutral until
  ADR-E0.5-03 closes.** The abstraction uses the AWS S3
  candidate from ADR-E0.5-03 without hard-coding cloud
  credentials; final launch-jurisdiction sign-off may
  swap the SaaS provider through the same
  `ObjectStorageProvider` contract.
- **Valkey ACL bootstrap relies on `mc`-equivalent
  pattern.** The Helm-hook Job renders the ACL file
  into a ConfigMap; the StatefulSet picks it up via
  `--aclfile=/acl/users.acl`. The chart never inlines
  a literal password; the per-user password is set by
  the operator via `ACL SETUSER` after first boot (the
  secret store resolves the per-user password from
  Vault). E14.1 owns the production procedure.
- **`aws-sdk-client-mock` test fixture placeholder.**
  `compatibility-matrix.yaml.testHarness.fixtures[aws-s3].env`
  carries `AWS_ACCESS_KEY_ID: AKIA-TEST-ONLY` + a
  matching `AWS_SECRET_ACCESS_KEY`. The fixture is for
  `aws-sdk-client-mock` (no real AWS call); the
  placeholder is documented in the source-of-truth
  comment. CI never reads this env var as a real AWS
  credential.
