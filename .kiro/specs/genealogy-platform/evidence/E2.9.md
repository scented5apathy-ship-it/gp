## Decisions

- **Four-eyes principle on production promotion.** Per
  `tasks.md` E2.9 ("Tách quyền merge code, đổi config
  production và approve promotion") + `architecture-decisions.md`
  ADR-E0.5-01 + `ownership-catalog.md` §3, no single
  identity can merge code, change production config
  AND approve promotion. The AppProject RBAC matrix
  enforces this with 4 roles (developer / config-reviewer
  / release-approver / platform-admin) + MFA on
  release-approver.
- **Argo Rollouts for progressive delivery.** Per
  `tasks.md` E2.9 ("Canary dựa trên error rate / latency;
  tự abort và rollback khi vượt threshold") +
  `design.md` §13 + ADR-E0.5-01, Argo Rollouts (Apache-2.0,
  no AGPL, no license cost) is the canonical progressive
  delivery engine. The chart renders the upstream
  controller + the 4 AnalysisTemplates (error-rate /
  latency-p95 / success-rate / saturation) + the 4
  service-class templates (stateless-api / bff /
  domain-event-consumer / async-worker).
- **Provider-neutral contract.** The chart renders the
  workload whenever `components.gitOps.driver: argocd`;
  external managed controllers set
  `driver: external` and bypass the workload. Domain
  code never branches on the driver.
- **Drift detection 180s + automatic rollback.** Per
  `ownership-catalog.md` §3 (SLO 99.9 %, rollout decision
  < 60 s) + `design.md` §13, the application-controller
  resyncs every 180 s + the Rollout strategy aborts on
  canary error rate > 5 % / latency p95 > 2000 ms /
  success rate < 98 % / CPU saturation > 92 %. The
  automaticRollback contract removes the human from the
  critical path; a release-approver only needs to
  re-promote the next roll.
- **AppProject RBAC + Keycloak OIDC SSO.** Per
  `architecture-decisions.md` ADR-E0.5-13 + E3.1, the
  Argo CD server authenticates via Keycloak OIDC (the
  `genealogy:developer` + `genealogy:config-reviewer` +
  `genealogy:release-approver` + `genealogy:platform-admin`
  groups). Anonymous access is FORBIDDEN; the
  `--disable-admin` flag forces the SSO path.
- **`dna-blackout` window for E10.2 isolation.** Per
  `tasks.md` E10.2, a release-approver + MFA human
  action is required to roll any DNA workload. The
  `dna-blackout` sync window enforces this 24/7.
- **Audit fields use `actor_pseudo_id` only.** Per
  `privacy-and-legal-gate.md` §11 + E3.6, every audit
  event uses `actor_pseudo_id` (never raw email / OIDC
  subject / user UUID). The deep linter rejects
  `email` / `raw_email` / `oidcSubject` in the audit
  fields list.
- **No literal secret in source-of-truth.** Per
  `agent-execution.md` §3, no literal admin password /
  server secret / signing key / OAuth client secret /
  Redis password. All credentials are resolved at runtime
  via ESO + Vault (E2.6 contract). The deep linter
  rejects any secret-shaped value in the source-of-truth
  files.

## Security and privacy

- **Tenant isolation: PASS.** The `gitops` contract stub
  forbids per-tenant AppProject / Application / Rollout /
  AnalysisTemplate. The deep linter rejects a
  tenant-shaped namespace (e.g. `tenant-<uuid>`) in any
  AppProject destination. Per the privacy gate
  (`privacy-and-legal-gate.md` §12), the Argo CD
  deployment is a per-cluster (NOT per-tenant) control
  plane; per-tenant isolation is enforced at the
  Application layer via OpenFGA + ABAC (E3.3 + E3.4).
- **Authorization/ABAC: PASS.** AppProject RBAC strict
  mode + four-eyes principle (developer /
  config-reviewer / release-approver / platform-admin)
  + MFA on production promotion. The release-approver +
  platform-admin roles carry `requiresMfa: true`.
- **Secret/PII/DNA leakage: PASS.** No literal secret /
  token / password / API key / private key / ssh-key in
  any file. All credentials are resolved at runtime via
  ESO + Vault (E2.6 contract). Audit fields use
  `actor_pseudo_id` only (no raw email / OIDC subject).
  `dna-blackout` sync window enforces E10.2 isolation:
  release-approver + MFA human action required to roll
  any DNA workload.
- **Dependency/config scan: PASS.** Argo CD `2.13.4` +
  Argo Rollouts `1.7.2` + Redis `7.2-alpine` are pinned
  per ADR-E0.5-01. Apache-2.0 / MIT / BSD; no AGPL on
  the SaaS control plane. Renovate bumps the patch line
  per ADR-E0.5-01.
- **Mesh + app retry disjoint: PASS.** Argo Rollouts
  uses Istio VirtualService for traffic splitting;
  Istio mesh retry is disabled (per E2.5). The Argo
  Rollouts controller retry budget (5 attempts × 3s
  backoff) is kept disjoint from the mesh retry budget
  (0 attempts) to prevent retry amplification per
  `design.md` §13.
