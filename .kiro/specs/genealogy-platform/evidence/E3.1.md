## Decisions

- ADR-E0.5-05 default = `realm-per-tenant-group`; dedicated realm
  opt-in for enterprise isolation; SAML = deprecated; OIDC = canonical.
- 5 mandatory clients per `tasks.md` E3.1 (R2 §R2.1).
- Authorization Code + PKCE S256 mandatory for every public /
  confidential client.
- Direct Access Grants + Implicit grant forbidden (R2 §R2.1).
- RS256 / 4096-bit realm signing key + 90-day rotation + 30-day
  client-secret rotation (NFR1 OWASP ASVS §2.10).
- JWKS algorithm allowlist excludes `none`, `HS256`, `HS512`.
- Federated `groups` claim is force-synced to `tenant_groups` user
  attribute. **The trust boundary for Keycloak group membership is
  the `tenant_groups` user attribute**, NOT the federated upstream
  group name. The `tenant-service` (E3.2) is the only authority that
  promotes federated subjects to canonical Keycloak groups.
- Helm chart stores 5 ConfigMaps + 7 ESO-managed Secrets. No
  literal credential in the repo.

### Security and privacy

- Tenant isolation: **PASS (config posture)** — the realm-strategy
  pins realm name to `genealogy-shared`; `tenant_pseudo_id` /
  `actor_pseudo_id` claims are emitted from user attributes that
  are populated only by `tenant-service` (E3.2). The contract
  forbids exposing `tenant_id` / `raw_dna` / `raw_pii` in any OIDC
  claim.
- Authorization/ABAC: **PASS (config posture)** — Keycloak only
  asserts identity + group membership; domain authorization stays in
  the destination service per `design.md` §4.1.
- Secret/PII/DNA leakage: **PASS (config posture)** — `script lint`
  rejects literal `password` / `apiKey` / `token` / `pepper` /
  `jwt` / `private_key` / `client_secret` values across all 5
  source-of-truth files. Federation denylist enforces
  `forbiddenFederatedAttributes`.
- Dependency/config scan: **PASS** — Keycloak 26.x pin per
  ADR-E0.5-01 baseline.

## Residual risks

- **PARTIAL** because the contract is fully declarative but the
  runtime bridge (native realm JSON export + Keycloak Admin REST
  reconciliation + helm chart render + container smoke + BFF session
  security) is not yet implemented in this commit. The remaining
  items are listed in the table above and belong to E3.5, E3.2,
  E15.1, E14.x, E2.10 hotfix.
- The Helm hook Job is rendered but the script it invokes is NOT
  shipped in this commit. The bootstrap Job will fail in
  `pre-install` until E3.5 ships the reconciliation script (or
  until the realm JSON export is implemented).
- The `KeycloakFixture` Testcontainer still runs without importing
  the E3.1 realm. `tenant-service` integration tests that depend
  on real Keycloak tokens must remain on WireMock until E3.5.
- Federated `groups` claim → `tenant_groups` force-sync is
  acknowledged as a privilege-boundary concern; the `tenant-service`
  reconciliation (E3.2) is the only authority that promotes
  federated subjects to canonical Keycloak groups. **Until E3.2
  ships, the contract forbids federated `groups` for SaaS
  production deployments.**
- The platform OIDC consumers (Grafana E2.10, Argo CD E2.9, Vault
  E2.6) currently declare their own `client_id` + realm name
  (`grafana`, `argocd`, `vault-operator`, realm `genealogy` /
  `genealogy-platform`). E3.5 must align them with the new
  `genealogy-shared` realm + `gp-edge` namespace.
