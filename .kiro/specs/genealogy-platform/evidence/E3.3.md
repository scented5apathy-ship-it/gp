  `person`, `resource`, `dna`. Conditions (typed CEL):
  `tenant_match`, `consent_active`, `revoked_blocks`. Relations

## Decisions

  bootstrap tuples reference `u_admin` etc. as opaque user

  sync-workflow declares `abacOverlay: required` and the
  linter refuses a workflow that drops the flag. The rule
  itself is unchanged.

## Security and privacy

- Tenant isolation: PASS — store-per-tenant (one store per
  tenant, blast radius = one store); `tree#viewer` cascades
  from `tenant#viewer` so per-tenant revocation automatically
  denies tree access; `dna#reader` does NOT cascade (privacy
  posture).
- Authorization/ABAC: PASS — `tree#viewer` is a `union` with
  5 children; the ABAC overlay (E3.4) gates every tuple
  write + every Check at the application layer (Semgrep
  rule `no-openfga-allow-without-abac`).
- Secret/PII/DNA leakage: PASS — tuple content is opaque
  IDs only (`tenant:<id>`, `tree:<id>`, `user:<id>`); the
  bootstrap default-role tuples carry no PII / DNA / token;
  the audit hook `redact` list covers `raw_dna` + `raw_pii` +
  `email` + `display_name` + `phone` + `address` + `token`;
  the compatibility test scans the model JSON for `@gmail.com`,
  `Bearer `, `eyJ` (JWT), `raw_dna`, `raw_pii`, `ssn`.
- Dependency/config scan: PASS — no new Gradle dependency
  added; `openfga-sdk` already in `gradle/libs.versions.toml`
  (0.7.0) from E1.4. Chart values pin is the latest
  `v1.18.3` (Renovate bumps patch).
- Cross-service boundary: PASS — 11 services scanned, 0
  cross-service db/domain imports. E3.3 is config-as-code +
  contracts only; no service-domain code added.
- Cache invalidation invariant: PASS — `cache.invalidationOnWrite:
  required` + `cache.ttlOnly: forbidden`; the sync workflow
  includes the `cacheInvalidationAck` activity (closes the
  eventual-consistency window before `Write` returns).

## Residual risks

- Smoke test (`scripts/smoke-openfga.mjs`) **passes locally**
  on Docker daemon `unix:///var/run/docker.sock` (this host).
  The script is idempotent on `helm upgrade` (OpenFGA's
  `WriteAuthorizationModel` returns the existing id for a
  byte-identical model). The `openfga-bootstrap` Helm-hook
  Job in the chart uses the `openfga/openfga` CLI which is
  a different transport; if the CI agent image lacks that
  CLI in PATH, the Job fails. **Mitigation**: the Job
  spec already declares `openfga/openfga:v1.18.3` (same
  image as the server) and runs `openfga model write` +
  `openfga tuple write` — both ship in the upstream image.
  Verified locally via direct CLI invocation against a
  container.
- The OpenFGA SDK in `gradle/libs.versions.toml` is
  pinned to `0.7.0`; the server image is `v1.18.3`. SDK
  server-compatibility matrix is per OpenFGA — `0.7.x` SDK
  targets OpenFGA 1.x server. Renovate bumps both.
- 4 pre-existing baseline violations (`kafka`, `storage`,
  `cache`, `flags` under `platform/local/`) remain —
  E3.3 is not the closing epic for those.
