## Decisions

- ADR-E0.5-02 (schema-per-service): the `audit_service` schema is the
  sole owner of the ledger + deletion-evidence tables.
- ADR-E0.5-06 (cache invalidation mandatory on every Write): N/A —
  the audit ledger is write-only; there is no read-cache to invalidate.
- `privacy-and-legal-gate.md` TM-03 (repudiation): SHA-256 hash chain
  plus append-only discipline per the contract.
- `privacy-and-legal-gate.md` TM-09 (legal-hold bypass):
  `retention.yaml::spec.legalHold.enforcement: HARD_BLOCK` + DPO
  override only.
- `ownership-catalog.md` §2.11 (audit-service ownership): SRE primary,
  DPO delegate for retention evidence, Security Engineering for
  separation of duties.
- `privacy-and-legal-gate.md` §11 (data classes): no raw DNA, no
  PII, no tokens in the audit payload; redactor enforces denyKeys
  + maskKeys + scrubPatterns BEFORE the event leaves the originating
  service.

## Security and privacy

- Tenant isolation: PASS — RLS + `FORCE ROW LEVEL SECURITY` on both
  `audit_entry` and `deletion_evidence`; `audit_tenant_isolation`
  policy matches `tenant_id = current_setting('app.tenant_id', true)`;
  DPO role (`audit_service_dpo`) is granted SELECT only and cannot
  mutate.
- Authorization/ABAC: PASS — DPO export requires both `requestedBy`
  and `approvedBy` (two-person rule); signed URL TTL 900 s, download
  limit 3, role `DPO` required.
- Secret/PII/DNA leakage: PASS — `AuditRedactor` drops `rawDna`,
  `biography`, tokens and scrubs free-text patterns (email, JWT, IPv4
  / IPv6, bearer token, SSN, DNA sequence). Tests cover both denyKeys
  and maskKeys paths.
- Dependency/config scan: PASS — no literal secret / token / password
  / DSN in any source-of-truth file (enforced by the linter's
  `FORBIDDEN_LITERALS`).
- Append-only discipline: PASS — `REVOKE UPDATE, DELETE` from the
  application role + `BEFORE UPDATE OR DELETE OR TRUNCATE` row
  trigger that raises `check_violation` (`reject_audit_mutation`).
