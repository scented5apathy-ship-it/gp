## Decisions

- **Service name kept as `genealogy-service`** per
  `ownership-catalog.md` §2.2. The E4.1 subtask only adds the
  tree package; renaming would require an ADR supersession.
- **Visibility / lifecycle / collaboration enums are closed sets**
  — they mirror the YAML contracts byte-for-byte. The
  `fromWire` helper accepts the canonical UPPER_SNAKE_CASE form
  only.
- **UNLISTED token plaintext never persisted.** Plaintext is
  generated with `SecureRandom` (32 bytes → URL-safe base64url
  no padding → 43 chars), returned to the caller ONCE in the
  issuance response, and only the SHA-256 fingerprint is stored
  on the `unlisted_token` row + emitted on the event bus.
- **Audit / outbox publisher** stays framework-free at the
  command-service surface. The actual Kafka relay (out of scope
  for E4.1) consumes the `tree_service.outbox` table. This
  keeps the command-service testable without an embedded broker.
- **Tree transfer** uses a dedicated `updateTenant(repo, fromTenantId)`
  to keep the RLS / CAS path correct across the tenant boundary;
  the regular `update` rejects tenant mismatches.
- **Quota baseline** is `500 trees / tenant`
  (`tree-policy.yaml::spec.maxTreesPerTenant`); final number
  ratified by E0.6 ownership catalog.
- **No raw DNA / biography / PII / access tokens** ever placed
  in event payloads per `design.md` §7.3 — verified by the
  linter's forbidden-token scan.

## Security and privacy

- Tenant isolation: PASS — `tree_tenant_isolation` and
  `unlisted_token_tenant_isolation` RLS policies on every
  tenant-scoped table; `FORCE ROW LEVEL SECURITY`; application
  role `tree_service_app` is scoped to the `tree_service`
  schema only per ADR-E0.5-02.
- Authorization/ABAC: PASS — issuance of UNLISTED tokens
  requires the tree visibility to be `UNLISTED`; the service
  rejects the command otherwise.
- Secret/PII/DNA leakage: PASS — the UNLISTED token plaintext
  is never persisted; the event payload carries the SHA-256
  fingerprint only; no raw DNA / biography / PII is placed in
  any event payload (enforced by the linter forbidden-token
  scan).
- Dependency/config scan: PASS — no literal secret / token /
  password / DSN in any source-of-truth file (linter +
  chart-mirror byte-equality enforced).
- Append-only audit: PARTIAL — the audit ledger is built in
  E3.6 (audit-service); the tree-service emits via the platform
  `KafkaAuditPublisher` once the gRPC / Kafka wiring lands in
  E4.x. The command service writes an outbox row per mutation;
  the audit consumer is wired in E4.7 / E4.x.

## Acceptance criteria (tasks.md line 327-331)

- [x] CRUD / archive / restore / transfer / delete.
  - `TreeCommandService` exposes `createTree / updateMetadata /
    changeVisibility / changeCollaborationMode / archive /
    restore / transfer / delete`. Each mutation emits the
    corresponding Avro event via the outbox.
- [x] Locale / timezone / calendar / branding / collaboration policy.
  - `Tree` carries `defaultLocale / defaultTimezone /
    defaultCalendar / branding`. `BrandingJson` provides a
    hand-rolled encoder/decoder for the `JSONB` column.
    `CollaborationMode` mirrors the contract closed-set.
- [x] Enforce `PRIVATE / UNLISTED / PUBLIC`.
  - `Visibility` is a closed enum; the `tree` table has a CHECK
    constraint; the `changeVisibility` command emits
    `TreeVisibilityChanged`.
- [x] UNLISTED token is hashed, has expiry, can be revoked.
  - `UnlistedToken` carries SHA-256 fingerprint (hex lower 64
    chars), `expiresAt`, `revokedAt`; the
    `unlisted-token.yaml` contract declares
    `maxLifetimeSeconds` (30 days) and
    `defaultLifetimeSeconds` (7 days).
- [x] Event published on visibility change for projection
  rebuild / drop.
  - `TreeCreated`, `TreeVisibilityChanged`, `TreeArchived`,
    `TreeRestored`, `TreeTransferred`, `TreeDeleted`,
    `UnlistedTokenIssued`, `UnlistedTokenRevoked` are emitted
    via the outbox writer; the relay consumer (out of scope
    for E4.1) forwards to Kafka / Apicurio per
    `contracts/events/genealogy/v1/`.

  the row. The transfer command assumes the actor has been
  authorised at the gRPC trusted-context layer (E3.5).
