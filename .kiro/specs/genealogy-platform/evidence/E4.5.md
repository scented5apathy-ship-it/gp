## Decisions

- Mirrored `design.md` §5.3 + §5.5 + §6.2: Event + Claim as **separate aggregates** (claims may exist standalone for research hypotheses; events attach 0+ claims optionally via `attachedEventId`).
- Closed-sets: 18 `lifeEventKinds` (incl. RECURRING_MEMORIAL + CUSTOM for culture-specific events: đám hỏi, lễ ăn hỏi, lễ đầy tháng), 10 `eventParticipantRoles` (Relationship vocabulary + WITNESS + OFFICIANT + INFORMANT), 3 `privacyClassifications` (PRIVATE/UNLISTED/PUBLIC mirroring Tree E4.1), 4 `certainties` (shared with E4.2/E4.3/E4.4), 4 `provenanceStatuses` (shared with E4.4), 7 `sourceReferenceKinds`.
- **Provenance invariant**: `IMPORTED + VERIFIED` is hard-denied at constructor AND at SQL CHECK level. `VERIFIED_BY_SOURCE` + `CORRECTION` only allowed with `ASSERTED|VERIFIED`. Imported claims NEVER default to verified — the platform surfaces the gap (R4.4 + R8).
- **Claim must carry ≥1 source reference** (`spec.claimRequiresSourceReference: true`); enforced at constructor and at invariant.
- **CORRECTION provenance requires `correctsClaimId` back-reference** (R4.4 + merge chain to E4.6).
- **RECURRING_MEMORIAL requires date** (R10 anniversary scheduler hook).
- `recurringMemorialRequired: [RECURRING_MEMORIAL]` (closed-set anchor for E5 scheduler).
- Audit hooks: `consent` class on every event / claim mutation; 7 audit action strings (`event.created` / `.updated` / `.deleted`; `claim.created` / `.updated` / `.verified` / `.disputed`).
- Confidence range `[0.0, 1.0]`; `null` is allowed (editor skip-a-number) and emits WARN.
- Sources cap 32 per claim (prevents unbounded citation blobs).
- Custom label cap 256 (matches Relationship); description cap 2048 (matches date-place).
- Provider-neutral: reuses E4.2 / E4.3 / E4.4 value objects (Person opaque id, Date, Place, Certainty, ProvenanceStatus).
- Assumptions: None (all closed-set values are derivable from the contract).
