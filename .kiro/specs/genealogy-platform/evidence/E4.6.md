## Decisions

- Mirrored `design.md` §5.2 + §6.2 + §7.3 + §8.3 + `glossary-and-policy-matrix.md` §2.4 (`MERGE` rule): Person is the merge root for E4.6; the losing Person is **retained as a tombstone** (`PersonLifecycle.MERGED`, already introduced in E4.2 with this exact semantic) and is NEVER hard-deleted (R4.5).
- Closed-sets: 1 `mergeKind` (`DUPLICATE_PERSON_MERGE`; RELATIONSHIP_MERGE / EVENT_MERGE / CLAIM_MERGE deferred per §4.4 scope guard — adding them requires a separate task), 5 `mergeStatusLifecycle` (`CANDIDATES_SCORED → REVIEWED → MERGED; REVERTED; REJECTED`), 4 `mergeProvenances` (`USER_REVIEW`, `AUTOMATED_SCORER`, `IMPORTED`, `CORRECTION`).
- **Scoring components pinned** to contract weights summing exactly 1.0: `NAME_EQUALITY` 0.4 + `DATE_PROXIMITY` 0.25 + `PLACE_PROXIMITY` 0.15 + `IDENTIFIER_MATCH` 0.2 (R4.5). The linter enforces sum = 1.0 ± 0.001 so the merge service is deterministic and the renderer can show per-component breakdown.
- **Auto-merge threshold = 0.85** and **manual-score floor = 0.5** and **revert window = 30 days**, all hard-pinned per `architecture-decisions.md` §A (`DRAFT` ratification list — E0.2 §5 #4 + §2.4 #6). The linter refuses any other value so the platform stays deterministic.
- **Source preservation required = true** (R5.5 + R8.5): the merge command re-keys `claim.subjectId` / relationship participants / event participants / media links from loser to winner but never touches a citation row or its media attachment; the merge record carries `rekeyedReferenceCount` so the operator can audit the work.
- **Redirect preservation required = true** (R4.5): external identifiers (`SHARE_TOKEN`, `PUBLIC_URL`) attached to a losing Person are reissued on the winner via `person_merge_redirect` rows; the original id is revoked. The 301 → winner mapping is what external callers hit (glossary §2.4 #5).
- **Revertibility**: `MERGED` is reachable to `REVERTED` only inside `revertWindowDays` (default 30, hard-pinned). The merge record carries a canonical `revertCommandJson` (winner/loser swap) so the reverter is deterministic (glossary §2.4 #2 + #6).
- **Self-merge forbidden**: `winner == loser` is hard-denied at constructor + SQL CHECK (R4.5 + NFR1 defense-in-depth).
- **Reviewer + reason required** for `MERGED` and `REVERTED` transitions (R10 + R16). `snapshotHash` is mandatory on `MERGED` so the reverter can prove the loser snapshot is intact.
- **Audit hooks** anchored: `candidate.scored`, `merge.compared`, `merge.previewed`, `merge.committed`, `merge.reverted`, `merge.rejected` — all `consent` class because merge shifts the privacy surface (R10 living-link redaction).
- **Re-key cap** = 10 000 references per merge transaction; merges that touch more rows are rejected with `REKEY_LIMIT_EXCEEDED` so the transaction stays atomic.
- **Cap on candidates per scoring run** = 1 000 (mirrors Relationship per-tree cap) so the renderer never receives an unbounded blob.
- **Reuses E4.2 PersonLifecycle.MERGED** tombstone semantic; **reuses E4.5 `correctsClaimId` chain** for correction provenance (merge → claim correction flows into the same audit trail).
- Assumptions: None — all numeric thresholds come from `architecture-decisions.md` §A; all closed-sets from the contract.
