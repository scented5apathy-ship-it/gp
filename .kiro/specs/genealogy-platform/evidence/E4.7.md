## Decisions

- ADR-E0.5-08 followed verbatim: Avro + Apicurio + BACKWARD compatibility + topic naming `<domain>.<aggregate>.<version>.v{n>` + partition key strategy.
- `design.md` §7.3 followed verbatim: transactional outbox → relay → Kafka; consumer inbox / idempotency; retry topic + dead-letter + replay procedure.
- Envelope serialization is Avro-only (mandatory per ADR-E0.5-08); JSON is the intermediate outbox encoding, the relay upgrades at publish time.
- Merge events partition key = `tenantId + "|" + aggregateId` (mandatory for cross-aggregate causal ordering per ADR-E0.5-08).
- Closed-set retry policy: max 5 attempts, exponential backoff (1s → 2 → 4 → 8 → 16 → clamped at 60) + ±25% jitter.
- Closed-set DLQ reason taxonomy; `TENANT_MISMATCH` and `UNKNOWN_TOPIC` are always permanent; `SCHEMA_INCOMPATIBLE` always permanent; transient retries stop at maxAttempts.
- Tenant-context check at publish time is defense in depth on top of RLS (RLS is enabled + forced on both `outbox` and `inbox_idempotency`).
- Producer abstraction (`KafkaProducerPort`) keeps the relay framework-free — production implementation wraps Confluent / Apicurio, unit tests use the `FakeProducer` fake.
- Inbox idempotency default = `EVENT_ID`; TTL = 7 days (matches projection-rebuild retention in ADR-E0.5-08).
- Audit hook class = `operational` (not `consent` / not `user`) because the relay is a platform-level operation; it never touches user PII.
- Assumptions: None — every threshold is pinned by `architecture-decisions.md` §A or ADR-E0.5-08; every closed-set is hard-pinned in the contract.
