## Security and privacy

- Tenant isolation: PASS — server route mounts `<PersonRoute>` only after `resolvePersonId(personId)` chấp nhận opaque id; client never trusts `tenantId` từ URL (E3.5); BFF validates membership per `PersonFetcher.getPersonPermissions({treeId,personId})` — UI only displays, BFF enforces.
- Authorization/ABAC: PASS — `PersonPermissions` được fetch song song với `PersonBody`; UI gates qua `canEditField`/`canAct` (R10); `PersonPatch.additionalProperties=false` ensures BFF không nhận field ngoài closed set; server still re-checks on PUT (design.md §8.3).
- Secret/PII/DNA leakage: PASS — `redaction` chỉ read từ server response, không re-redact; `displayName` empty khi `redacted=true`; place query < 2 chars / > 128 chars → throw; PlaceProvider throws → degraded mode; no token / PII / DNA logged anywhere; forbidden-token scan trong linter catches AKIA / BEGIN PEM / DSN.
- Dependency/config scan: N/A (không thêm dependency mới — chỉ dùng `@genealogy/api-client` đã có từ E1.5).
- Tenant bypass: PASS — every store path takes `treeId` + `personId` qua `PersonEditorQuery`, validated opaque regex `^[A-Za-z0-9._:-]{1,128}$` mirroring BFF contract.
- Cache invalidation: N/A — store is in-memory, no caching; BFF/Valkey contract unchanged (E2.7).
