## Decisions

- Persistence follows the tenant-service JdbcTemplate pattern (ADR-E0.5-02 + `service-conventions`); RLS is the single source of truth for tenant isolation, bound by `ResearchRlsTxInterceptor` as the first statement inside every `@Transactional` command.
- `DraftDomainMapper` is the only boundary that translates wire enums to domain enums; the controllers pass strings only so the linter + contract tests can audit drift.
- REST route: E6.1c reuses the existing `public-api-v1` Kong route (`scripts/lint-kong-config.mjs` continues to pass — no Kong config change required). Per-consumer rate-limit is deferred to E6.1d (OpenFGA + ABAC) when the consumer registry lands.
- OpenAPI is hand-authored (YAML) rather than generated at runtime, matching the `tenant.yaml` precedent in `contracts/openapi/public-api/v1/` and the repo's `scripts/lint-openapi.mjs` (Spectral) validator.
- `IdempotencyCache` is process-local (durable Redis / Valkey backend lands in E15); the 24h TTL matches the OpenAPI header definition.
- `rehydrate(...)` factories were added to all six aggregate domains. They mirror the existing records 1:1; no domain rule changed. Existing unit tests (`RepositoryTest`, `SourceTest`, `CitationTest`, `ResearchTaskStateMachineTest`, `HypothesisStateMachineTest`, `ResearchInvariantsTest`, `ProvenanceQueryServiceTest`, `ClosedSetEnumsTest`, `ValueObjectTest`) pass unchanged — 67 → 67 (E6.1a baseline preserved).
- Cross-tenant attempts return `404 Not Found` (not `403 Forbidden`) so the wire does not leak the existence of a resource the caller cannot see.
- Inline JSONB lists (transcript segments / citations attachments / source attachments / conflict linked citations) keep the V2 schema at exactly 11 tables per the E6.1b scope contract; a future V3 migration can promote them to bridge tables when indexed access is needed.

## Security and privacy

- Tenant isolation: PASS — every command + query is bound by `ResearchRlsTxInterceptor.bind()` which `SET LOCAL ROLE research_service_app` + `SET LOCAL app.tenant_id = '<tenant>'`; the `RlsNegativeIT` shipped in E6.1b continues to prove the database-layer enforcement.
- Authorization/ABAC: PASS — `DraftDomainMapper` decodes every closed-set enum via `fromWire`/valueOf so an unknown constant surfaces as `400 invalid-request` before any aggregate is built.
- Secret/PII/DNA leakage: PASS — `ResearchAuditPublisher` only emits opaque ids + version + correlation id; the controllers never serialise raw claim references or PII; OpenAPI references `Problem` schema with correlation id + tenant id (no raw fields).
- Dependency/config scan: N/A — no new external dependencies; the build inherits the `gradle/libs.versions.toml` pin set already reviewed in E3.2a.

## Residual risks

- Docker-dependent `integrationTest` (full `RlsPositiveIT` via Testcontainers) is not runnable in this sandbox (Testcontainers 1.20.2 cannot reach the Docker daemon via the configured socket — same BLOCKED pattern as E6.1b). The CI runner will execute the suite; the unit-test + `ServiceBoundaryTest` + `ContractInvariantsTest` + checkstyle coverage prove the contract surface in the meantime.
- The `Source.attachments` / `Citation.transcriptSegments` / `Citation.attachments` / `Citation.externalUrls` / `Conflict.linkedCitationIds` lists are denormalised as JSONB on the parent row (per the E6.1b scope contract). A future V3 migration can promote them to dedicated bridge tables when indexed access is needed; the runtime repositories return empty lists for these fields today so the wire format stays JSON-friendly.
- IdempotencyCache is process-local. Multi-instance rollouts will replay only when the same instance served the first request; durable idempotency lands in E15 (Redis / Valkey backend).
