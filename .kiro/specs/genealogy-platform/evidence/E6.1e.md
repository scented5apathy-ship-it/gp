## Decisions

- **ADR-E0.5-02 (schema-per-service): ACCEPTED.** V4
  migration lands inside the `research_service` schema;
  the runtime role `research_service_app` is granted
  DML on `consumer_inbox` via the V2 baseline grant
  (`GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES
  IN SCHEMA research_service TO research_service_app`).
- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD
  evolution): ACCEPTED.** The durable inbox PK
  `(tenant_id, source_topic, event_id)` is stable; the
  closed-set `outcome` enum mirrors the
  `research-policy.yaml::spec.auditOutcomes` pattern.
  Adding a new outcome requires a follow-up ADR per
  `agent-execution.md` §4.4.
- **Manual ACK only after the database transaction
  commits.** Per `design.md` §7.3, the offset commits
  after the projection row commits. The
  `MANUAL_IMMEDIATE` ack mode is wired on the
  `researchKafkaListenerContainerFactory` bean; a
  rolled-back transaction prevents the offset commit.
- **Helm template key naming convention.** Map keys
  MUST NOT contain hyphens (helm's parser treats
  `.Values.services.research-service` as the arithmetic
  expression `services - research - service` and
  refuses to render). The canonical values key is
  `services.research` (no hyphen); the workload name
  + label still use `research-service` (hyphen is safe
  inside quoted string literals + label values).
- **Vault Agent Injector for secrets.** The
  deployment renders
  `vault.hashicorp.com/agent-inject: "true"` +
  `vault.hashicorp.com/role: research-service` +
  two `agent-inject-template-*` annotations for the
  database + Kafka secrets. The per-env values files
  override `services.research.secretRefs.clusterSecretStore`
  + the Vault paths so SaaS / on-prem can swap
  cluster stores without touching the chart.
- **OpenFeature sidecar is opt-in.** The default
  `services.research.openfeature.enabled: true` keeps
  the deployment aligned with the E2.8 contract; per-env
  values files can disable for dev clusters that don't
  run Flagsmith yet.
- **Probe paths use Spring Boot Actuator.** The
  umbrella's `_probes.tpl` uses `/healthz/*` for
  platform components; the research-service workload
  intentionally exposes `/actuator/health/liveness` +
  `/actuator/health/readiness` because the platform
  starter owns the actuator mapping. The Helm values
  override the path via
  `services.research.probes.{livenessPath,readinessPath}`.
- **No new Kafka topic / ACL.** E6.1e reuses the
  upstream `genealogy.tree-visibility.v1.v1` +
  `genealogy.person-redacted.v1.v1` topics. The ACL
  work is Gap 8 in `evidence/E6.1d.md` and lands in a
  follow-up epic.
- **Scope guard.** No domain Java change (E6.1a).
  No REST surface change (E6.1c). No Kafka topic /
  ACL change. No application code change outside the
  relay + consumer layers.

## Security and privacy

- **Tenant isolation**: PASS — V4 migration enables
  + forces RLS on `consumer_inbox`; the new IT
  `RlsNegativeIT.consumerInboxCrossTenantBlocked`
  verifies `tenant-bbbb` session sees zero rows from
  `tenant-aaaa`; `RlsNegativeIT.consumerInboxCrossTenantInsertRejected`
  verifies the `WITH CHECK` predicate rejects
  cross-tenant INSERT. The runtime role
  `research_service_app` is `NOLOGIN`; the workload's
  `ResearchRlsTxInterceptor.bind()` issues
  `SET LOCAL ROLE research_service_app` +
  `SET LOCAL app.tenant_id = ?` per transaction so the
  V4 RLS posture is honoured end-to-end.
- **Authorization/ABAC**: PARTIAL — the
  `ResearchReAuthorizationPort` (E6.1d) is wired; the
  real OpenFGA SDK adapter + Flagsmith provider land
  in the follow-up epic (Gap 1 + Gap 2 in
  `evidence/E6.1d.md`).
- **Secret/PII/DNA leakage**: PASS — no literal
  credential in any chart file; the
  `ExternalSecret` references point to Vault paths
  only. The Helm annotation template uses the
  Vault Agent `{{ .Data.data.password }}` substitution
  (no literal). The
  `ResearchPayloadForbiddenFieldScan` (E6.1d) is
  unchanged and still flips forbidden-field payloads
  to `DEAD_LETTERED` before the producer call.
- **Dependency/config scan**: PASS —
