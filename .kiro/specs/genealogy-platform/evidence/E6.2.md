## Decisions

- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD evolution): ACCEPTED** — every closed-set vocabulary (proposalKinds, proposalStatuses, proposalDecisions, domainCommandKinds, reviewVerdicts, reviewStatuses, conflictResolutions, reAuthorizationOutcomes) is anchored to the YAML contract; the Java enum values are pinned alphabetically so the linter can compare them. Adding a new value requires an ADR supersession.
- **ADR-E0.5-01 (Java 21 toolchain): ACCEPTED** — `services/collaboration-service/build.gradle.kts` now applies `java-conventions` + `service-conventions` (ArchUnit boundary guard).
- **No cross-service domain import** — `CollaborationInvariants.FORBIDDEN_DOMAIN_COMMAND_FIELDS` + `FORBIDDEN_PROPOSAL_KIND_OPERATIONS` are local static maps; the ArchUnit boundary guard blocks accidental coupling to other services. Verified by `pnpm check:boundary` → clean.
- **In-memory executor only** — E6.2 vessels the executor in pure records + state machines + `PartialMergeExecutor`. The Flyway migration + jOOQ repository + Kafka producer/consumer + OpenAPI / gRPC stubs land in the later E6.x / E11.x sub-epics. The platform `ownership-catalog.md` §2.4 makes this explicit (`Sync dep budget: n_sync ≤ 1`).
- **E6.2 keeps the editor + UI out of scope** per `agent-execution.md` §4.4. Per the user's explicit choice on the §4.4 scope question, the implementation commits the domain + invariants + partial-merge executor + re-authorization port + linter + tests but defers the openapi.yaml, gRPC stubs, Flyway migration, Kafka producer/consumer and Vue / React components to the later E6.x sub-epics. Mixed-collaboration policy (E6.3, the per-role / per-branch / per-resource-type direct edit vs approval rule) is also deferred and routes through the closed-set `proposalKinds` + `domainCommandKinds` so the E6.3 wiring does not require schema changes.
- **Audit metadata uses `actorPseudoId` only** — never raw user id / email / DNA. Mandated by `CollaborationAuditAttributes` compact constructor + audit contract `auditActorKey: actorPseudoId` / `auditCorrelationKey: correlationId`. Reviewer + proposer carry pseudo id only (per R10.6).
- **Separation of duties** — `Review` constructor refuses to accept a `reviewerPseudoId` equal to `proposerPseudoId`. Pin test: `ReviewTest.reviewRejectsReviewerEqualsProposer` (would have been cleaner as `createRejectsReviewerEqualsProposer`; the test class names follow the existing research-service convention).
- **Forbidden fields** — `FORBIDDEN_DOMAIN_COMMAND_FIELDS` is closed-set (12 entries). The `DomainCommand` constructor + `CollaborationInvariants.check` + `PartialMergeExecutor` all reject any `fieldChanges` key that matches. Adding a key requires an ADR supersession.
- **Forbidden operations per proposal kind** — `FORBIDDEN_PROPOSAL_KIND_OPERATIONS` is closed-set (e.g. `PERSON` forbids `SET_TREE_VISIBILITY`, `TREE_VISIBILITY` forbids every CRUD operation on Person / Relationship / LifeEvent / Claim / Source / Citation). The map is exposed by the policy contract AND enforced by the executor.
- **Re-authorization at every decision point** — `reAuthorizationOnSubmit / reAuthorizationOnApprove / reAuthorizationOnPartialMerge` are pinned to `true`. `reAuthorizationDenyClosesProposal` + `reAuthorizationAbacDenyClosesProposal` are pinned to `true`, so a DENY or ABAC_DENY at submit closes the proposal immediately (verified by `ChangeProposalTest.submittedRequiresReAuthorization` + `PartialMergeExecutorTest.denyReAuthorizationClosesProposalDuringMerge` + `CollaborationInvariantsTest.denyReAuthorizationClosesProposal` + `CollaborationInvariantsTest.abacDenyReAuthorizationClosesProposal`).
- **Base version is part of the contract** — `DomainDiff.baseVersion` MUST equal `ChangeProposal.baseResourceVersion` (enforced by the compact constructor). Every `DomainCommand.baseVersion` MUST equal the diff's `baseVersion` (enforced by `PartialMergeExecutor`). The proposal can never silently bypass optimistic concurrency.
- **No new dependency added** — `services/collaboration-service/build.gradle.kts` keeps the existing `spring-boot-starter-actuator + postgres + flyway + openfeature` baselines + the `archunit-junit5:1.3.0` transitive brought in by `service-conventions`. No new Maven coordinates.
- **Single source of truth** — the YAML contract under `contracts/collaboration/` is the cross-service reference; the platform mirror at `platform/helm/genealogy-platform/files/collaboration-proposal-policy.yaml` is byte-identical and enforced by the linter. The E4.1 per-tree collaboration mode file (`contracts/genealogy/collaboration-policy.yaml` + helm mirror) is preserved untouched so `lint-tree-config` keeps working.

## Security and privacy

- **Tenant isolation**: PASS — every aggregate carries `TenantScopedId` (R10.1 + NFR1); compact constructor rejects tenant mismatch on `Review`. `ChangeProposal.affectedResourceIds` + `DomainCommand.resourceId` use the safe-character set + length caps, mirroring `TenantScopedId`.
- **Authorization/ABAC**: PASS — `CollaborationInvariants.check` emits DENY on `PROPOSAL_REAUTHORIZATION_DENIED` + `PROPOSAL_REAUTHORIZATION_ABAC_DENIED` when the `ReAuthorizationDecision.outcome` is not `ALLOW`. `PartialMergeExecutor` rejects DENY / ABAC_DENY re-auth by closing the proposal with `MergeOutcome.Kind.DENY_CLOSES_PROPOSAL`. The `ReAuthorizationPort` interface enforces the closed-set `ReAuthorizationOutcome` enum so OpenFGA / ABAC raw verdicts never enter the executor or the log.
- **Secret/PII/DNA leakage**: PASS — `CollaborationAuditAttributes` rejects raw identifiers; `auditActorKey` is pinned to `actorPseudoId`; the linter forbids `password[:=]`, `token[:=]`, `secret[:=]`, `api[_-]?key`, `authorization`, `bearer`, `raw[_-]?dna`, `raw[_-]?ssn`, `raw[_-]?passport` in `spec.forbiddenPayloadPatterns`. No token / raw PII / DNA appears in any log path.
- **Dependency/config scan**: PASS — `pnpm check:boundary` clean; `pnpm check:gradle:lock` clean. No new direct dependencies.

## Residual risks

- **REST / gRPC / Flyway / Kafka / OpenAPI stage deferred** — these are sequenced for E6.3+ per the user's explicit scope choice on the §4.4 question. The E6.2 evidence file does not claim them as DONE; the closed-set vocabularies + the executor's deterministic behaviour are the contract guarantee that the upcoming sub-epics can keep the policy in lockstep.
- **Mixed-collaboration policy (R10.4) deferred to E6.3** — the per-role / per-branch / per-resource-type direct edit vs approval rule lives in the policy contract (`spec.forbiddenProposalKindOperations` + the upcoming `spec.directEditMatrix`) but the application-level wiring is E6.3 per the catalog ordering.
- **Re-authorization is a port** — the `ReAuthorizationPort` is a `@FunctionalInterface` with no default implementation; the application layer injects a Spring adapter that calls OpenFGA + the ABAC overlay in the later E6.x sub-epics. The contract is closed-set + ABAC deny-closes-proposal so the adapter cannot silently weaken the guarantee.
