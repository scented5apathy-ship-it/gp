## Decisions

- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD evolution): ACCEPTED** — every closed-set vocabulary anchored to the YAML contract; the Java enum values are pinned alphabetically and validated by the linter. Adding a new value requires an ADR supersession.
- **ADR-E0.5-01 (Java 21 toolchain): ACCEPTED** — `services/collaboration-service/build.gradle.kts` keeps the `java-conventions` + `service-conventions` plugins (Java 21, Checkstyle, ArchUnit boundary guard).
- **YAML contract is the source of truth** — Flagsmith only carries a rollout switch (`collab.mixedPolicy.v2`) and a snapshot version. The matrix + the closed-set vocabularies live in `contracts/collaboration/mixed-collaboration-policy.yaml` and the helm mirror. The `flagsmithRolloutContractSupersedesFlag` toggle is pinned to `true`; the `flagsmithSafeDefaultValue` is pinned to `false` so the platform starts in the safe-default before the first snapshot is loaded.
- **Hard-coded guard rails cannot be relaxed** — `ALWAYS_APPROVAL_REQUIRED` (TREE_VISIBILITY / CLAIM / SOURCE) + `DIRECT_EDIT_FORBIDDEN_ROLES` (VIEWER / CONTRIBUTOR) + `DIRECT_EDIT_PERMITTED_RESOURCES` (LIFE_EVENT / CITATION) are constants in `DirectEditMatrix` and the executor. The YAML contract mirrors them so the linter can detect drift.
- **DirectEditMatrix as a flat list** — the YAML contract stores the matrix as a list of records (`role / branch / resourceType / decision`) rather than a nested map. The loose YAML parser + the linter can validate each entry independently; the Java `DirectEditMatrix` constructor flattens the list into a `Map<CollaborationRole, Map<TreeBranch, Map<RoutingResourceType, RoutingDecision>>>` for O(1) lookup.
- **No arbitrary JSON patch on forbidden fields** — `PatchValidator` rejects every key that is in `FORBIDDEN_DOMAIN_COMMAND_FIELDS` (E6.2) + every value exceeding the length cap. The `MergeCommandFactory` re-validates the manual merge plan against the same forbidden field set before materialising a domain command.
- **Conflict comparison is an additive model** — every conflict carries a `ConflictFieldKind` (SAME / DIFFERENT / ONLY_BASE / ONLY_INCOMING / ONLY_LOCAL). The UI renders the comparison model from this list; the merge command factory only auto-merges when every field is `SAME` (or `ONLY_BASE` / `ONLY_LOCAL`, which are local-only modifications).
- **Flagsmith snapshot is validated** — the sync executor rejects snapshots older than `flagsmithSnapshotMaxAgeSeconds` (default 900s) + snapshots whose strategy is not in the closed-set + snapshots whose `KILL_SWITCH` is enabled. The `contractSupersedesFlag` toggle makes the YAML contract the authoritative source: a `PROGRESSIVE` snapshot whose `enabled==false` is treated as `STALE` (rollout not yet enabled).
- **No cross-service domain import** — the ArchUnit boundary guard (`ServiceBoundaryTest`) blocks accidental coupling to other services. `patchValidationForbiddenFields` reuses the E6.2 `CollaborationInvariants.FORBIDDEN_DOMAIN_COMMAND_FIELDS` map; the linter cross-validates the two closed-sets.
- **In-memory executor only** — E6.3 vessels the routing + merge + Flagsmith sync logic in pure records + executors. The Flyway migration + jOOQ repository + Kafka producer/consumer + OpenFeature wiring land in the later E6.x / E11.x sub-epics. The platform `ownership-catalog.md` §2.4 makes this explicit (`Sync dep budget: n_sync ≤ 1`).
- **No new dependency added** — `services/collaboration-service/build.gradle.kts` keeps the existing `spring-boot-starter-actuator + postgres + flyway + openfeature` baselines + the `archunit-junit5:1.3.0` transitive brought in by `service-conventions`. No new Maven coordinates.
- **Audit metadata uses `actorPseudoId` only** — never raw user id / email / DNA. Mandated by `CollaborationAuditAttributes` (E6.2) + the 11 audit hooks in the E6.3 contract. Flagsmith sync carries `flagsmithSyncRequiredAuditKeys` (`actorPseudoId`, `correlationId`, `flagsmithEnvironmentId`, `flagsmithSnapshotVersion`).
- **Single source of truth** — the YAML contract under `contracts/collaboration/mixed-collaboration-policy.yaml` is the cross-service reference; the platform mirror at `platform/helm/genealogy-platform/files/collaboration-mixed-policy.yaml` is byte-identical and enforced by the linter. The E6.2 per-tree collaboration policy file (`contracts/collaboration/collaboration-policy.yaml`) and the E4.1 per-tree collaboration mode file (`contracts/genealogy/collaboration-policy.yaml`) are preserved untouched.

## Security and privacy

- **Tenant isolation**: PASS — every aggregate carries `TenantScopedId` (R10.3 + NFR1); compact constructor rejects tenant mismatch on `RoutingRequest`. The `resourceId` + `proposedBaseVersion` follow the safe-character set + length caps, mirroring `TenantScopedId`.
- **Authorization/ABAC**: PASS — `DirectEditMatrix.decide` + `RoutingExecutor.route` respect the per-role / per-branch / per-resource-type routing but never issue a direct edit on a resource type that is not in `DIRECT_EDIT_PERMITTED_RESOURCES` (LIFE_EVENT / CITATION). The E6.2 `CollaborationInvariants` + `PartialMergeExecutor` already enforce the per-proposal-kind forbidden operations; the E6.3 `MergeCommandFactory` re-validates the manual merge plan against the same forbidden field set.
- **Secret/PII/DNA leakage**: PASS — `PatchValidator` rejects fields in `FORBIDDEN_DOMAIN_COMMAND_FIELDS` (12 entries). The linter forbids `password[:=]`, `token[:=]`, `secret[:=]`, `api[_-]?key`, `authorization`, `bearer`, `raw[_-]?dna`, `raw[_-]?ssn`, `raw[_-]?passport` in `spec.forbiddenPayloadPatterns`. The Flagsmith sync audit carries `actorPseudoId` + `flagsmithEnvironmentId` + `flagsmithSnapshotVersion` only — never raw identifiers.
- **Dependency/config scan**: PASS — `pnpm check:boundary` clean; `pnpm check:gradle:lock` clean. No new direct dependencies.

## Residual risks

- **REST / gRPC / Flyway / Kafka / OpenAPI stage deferred** — these are sequenced for E6.4+ per the user's explicit scope choice on the §4.4 question. The E6.3 evidence file does not claim them as DONE; the closed-set vocabularies + the executor's deterministic behaviour are the contract guarantee that the upcoming sub-epics can keep the policy in lockstep.
- **Flagsmith adapter is a port** — the `FlagsmithSnapshot` is a pure record; the application layer injects a Spring adapter that calls the Flagsmith REST API in the later E6.x sub-epics. The contract is closed-set + `contractSupersedesFlag` + `killSwitchRefusesAllDirectEdits` so the adapter cannot silently weaken the guarantee.
- **Direct edit grants locked per (role, branch, resourceType) tuple** — the E6.3 contract is a positive allowlist. If a future tenant requires a more granular policy (e.g. per person or per tag), the matrix must be extended with a new field + a new ADR. The `flagsmithRolloutContractSupersedesFlag` toggle ensures the gradual rollout happens on the Flagsmith side, never on the contract side.
