## Decisions

- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD evolution): ACCEPTED** — every closed-set vocabulary anchored to the YAML contract; the Java enum values are pinned alphabetically and validated by the linter. Adding a new value requires an ADR supersession.
- **ADR-E0.5-01 (Java 21 toolchain): ACCEPTED** — `services/collaboration-service/build.gradle.kts` keeps the `java-conventions` + `service-conventions` plugins (Java 21, Checkstyle, ArchUnit boundary guard).
- **YAML contract is the source of truth** — the 12 closed-set vocabularies + the 5 guard rails + the 19 numeric bounds + the 28 invariant reason codes live in `contracts/collaboration/comments-activity-policy.yaml` and the helm mirror. The Java executor mirrors the contract; the linter enforces it.
- **Activity feed re-projection is mandatory** — `activityFeedAlwaysReproject=true` + `activityFeedSnapshotRawPayloadAllowed=false` + `activityFeedRedactedFieldMarker=[REDACTED]`. The `ActivityFeedItem.redacted(...)` factory pins the summary to `[REDACTED]`; the `ActivityFeedCollector` replaces any item that references a sensitive field with a redacted variant.
- **Sensitive field references force HIDDEN / REDACTED** — `Comment.mentionsSensitiveField(body)` detects 10 fields (DNA raw data, DNA match id, consent receipt, living marker, visibility, redacted fields, raw email / phone / ssn / passport) and rejects the comment at construction time unless status is HIDDEN / REDACTED. The `ActivityRedactionFilter` exposes the same closed-set to the application layer.
- **Notification hook never copies raw payload** — `notificationHookNeverCopyRawPayload=true` + `notificationHookTemplateRequired=true`. The `NotificationHook` compact constructor enforces the 4096-byte UTF-8 payload cap + the `templateKey` non-blank rule + the DELIVERED-without-redactionReason rule. The `NotificationHookDispatcher` maps DENY → DROPPED, ABAC_DENY → REDACTED + `RedactionReason.RAW_PII_DETECTED`.
- **Comment authorization is re-checked at every step** — `mentionReAuthorizationRequired=true` + `watchReAuthorizationRequiredOnTrigger=true` + `assignmentReAuthorizationRequiredOnAccept=true` + `activityFeedReAuthorizationRequiredOnRead=true` + `notificationHookReAuthorizationRequiredOnDispatch=true`. The `CommentAuthorizationPort` interface exposes the 11 action kinds; the `CommentAuthorizer` + `ActivityFeedFilter` + `NotificationHookDispatcher` call the port and require a non-blank `COLLAB_` reason code for DENY / ABAC_DENY.
- **Re-authorization denial closes the subscription** — `reAuthorizationDenyClosesSubscription=true` + `reAuthorizationAbacDenyClosesSubscription=true`. The `Assignment.accept(...)` / `Assignment.decline(...)` factories stamp `closedAt` so the assignment record is terminal.
- **Closed-set reason codes** — 28 invariant reason codes pinned to the YAML contract; the linter enforces the closed-set. Adding a new code requires an ADR supersession.
- **No cross-service domain import** — the ArchUnit boundary guard (`ServiceBoundaryTest`) blocks accidental coupling to other services. `Comment.MENTION_SENSITIVE_FIELDS` reuses the E6.2/E6.3 `CollaborationInvariants.FORBIDDEN_DOMAIN_COMMAND_FIELDS` map; the linter cross-validates the closed-set.
- **In-memory executor only** — E6.4 vessels the comment / mention / watch / assignment / activity feed / notification hook logic in pure records + executors. The Flyway migration + jOOQ repository + Kafka producer/consumer + OpenFeature wiring + the Spring adapter that calls OpenFGA + ABAC land in the later E6.x / E11.x sub-epics. The platform `ownership-catalog.md` §2.4 makes this explicit (`Sync dep budget: n_sync ≤ 1`).
- **No new dependency added** — `services/collaboration-service/build.gradle.kts` keeps the existing `spring-boot-starter-actuator + postgres + flyway + openfeature` baselines + the `archunit-junit5:1.3.0` transitive brought in by `service-conventions`. No new Maven coordinates.
- **Audit metadata uses `actorPseudoId` only** — never raw user id / email / DNA. Mandated by `CollaborationAuditAttributes` (E6.2) + the 9 audit hook toggles in the E6.4 contract. The `auditRequiredKeys` are `actorPseudoId` + `correlationId` + `targetPseudoId`.
- **Single source of truth** — the YAML contract under `contracts/collaboration/comments-activity-policy.yaml` is the cross-service reference; the platform mirror at `platform/helm/genealogy-platform/files/collaboration-comments-activity-policy.yaml` is byte-identical and enforced by the linter. The E6.2 / E6.3 / E4.1 contract files are preserved untouched.

## Security and privacy

- **Tenant isolation**: PASS — every aggregate carries `TenantScopedId` (R10.5 + NFR1); compact constructor rejects tenant mismatch on `Comment` + `Mention` + `Watch` + `Assignment` + `ActivityFeedItem` + `NotificationHook`. The `targetPseudoId` + `scopeId` follow the safe-character set + length caps, mirroring `TenantScopedId`.
- **Authorization/ABAC**: PASS — `CommentAuthorizer` + `ActivityFeedFilter` + `NotificationHookDispatcher` respect the per-scope / per-action authorization policy. The `CommentAuthorizationPort` interface is the only place the application layer calls OpenFGA + ABAC; the executor never mutates another service's domain record directly. ABAC denial forces REDACTED status + living minor / DNA consent revoked redaction reason.

The `NotificationHook` never copies a raw domain payload; the `sanitizedPayload` is a string-to-string map with a 4096-byte UTF-8 cap. The `ActivityFeedItem` summary is pinned to `[REDACTED]` when a sensitive field is detected.

## Residual risks

- **REST / gRPC / Flyway / Kafka / OpenAPI stage deferred** — these are sequenced for E6.5+ per the user's explicit scope choice on the §4.4 question. The E6.4 evidence file does not claim them as DONE; the closed-set vocabularies + the executor's deterministic behaviour are the contract guarantee that the upcoming sub-epics can keep the policy in lockstep.
- **OpenFGA + ABAC adapter is a port** — the `CommentAuthorizationPort` is a pure interface; the application layer injects a Spring adapter that calls OpenFGA + ABAC in the later E6.x / E11.x sub-epics. The contract is closed-set + `reAuthorizationDenyClosesSubscription` + `reAuthorizationAbacDenyClosesSubscription` so the adapter cannot silently weaken the guarantee.
- **Notification template key is opaque** — the `templateKey` is a string closed-set by the application layer; the contract accepts any non-blank string ≤ 64 chars. The application layer wires the actual template key map at the later E6.x / E11.x stage.
- **Activity feed retention is bounded** — `maxActivityFeedRetentionSeconds=31536000` (1 year). The retention policy is enforced by the application layer; the executor provides the projection timestamp.
