## Decisions

- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD evolution): ACCEPTED** — every closed-set vocabulary anchored to the YAML contract; the Java enum values are validated by the linter. Adding a new value requires an ADR supersession.
- **ADR-E0.5-01 (Java 21 toolchain): ACCEPTED** — `services/media-service/build.gradle.kts` applies the `java-conventions` + `service-conventions` plugins (Java 21, Checkstyle, ArchUnit boundary guard).
- **YAML contract is the source of truth** — the 10 closed-set vocabularies + the 9 guard rails + the 18 numeric bounds + the 55 invariant reason codes live in `contracts/media/upload-lifecycle-policy.yaml` and the helm mirror. The Java executor mirrors the contract; the linter enforces it.
- **Idempotent finalize on the same checksum** — `finalizeIdempotentOnChecksum=true`. The `UploadSession.idempotentFinalize(...)` short-circuits on the same checksum when status is QUARANTINED, throws on already-finalized sessions. The contract mirrors E6.4 `idempotentFinalize` semantics.
- **DNA bucket prefix shield** — `dnaBucketAccess=FORBIDDEN` + `dnaBucketPrefixes=[dna/raw, dna/match, dna/consent]` + `dnaSensitiveMimeHints=[application/x-fasta, application/x-fastq, application/octet-stream+dna]`. The `MimePolicy.routesToDnaBucket(...)` rejects any object key starting with these prefixes; the `UploadAuthorizer` rejects any object key starting with `dna/` for an `OCR_INPUT` intent. The DNA upload pipeline is sequenced for E7.4 (protected delivery).
- **MIME policy is per-category** — `mimeAllowList` is an object keyed by `MediaCategory`. Wildcards are NOT allowed; the executor enumerates every MIME type. Adding a new MIME type requires an ADR supersession.
- **Quota policy is three-dimensional** — `bytes + items + seconds`. The `QuotaLedger` carries an independent counter for each dimension and rejects overflow on any single dimension. `quotaHeadroomInBytes` is a global `1 GiB` reserve so a single tenant cannot starve the platform.
- **Sandbox + deep-scan classification** — `mimeSandboxRequired` + `mimeDeepScanRequired` are explicit closed-sets. DEEP_SCAN_REQUIRED takes precedence over SANDBOX_REQUIRED (Apache Tika + OCR + libvips need metadata extraction). The `QuarantineGate` keeps the session in QUARANTINED until the antimalware + metadata index checks pass.
- **Forbidden payload scan** — the linter forbids `credential`, `api[_-]?key`, `private[_-]?key`, `authorization`, `bearer`, `raw[_-]?dna`, `raw[_-]?ssn`, `raw[_-]?passport`, `fastq`, `dna[_-]?raw` in `spec.forbiddenPayloadPatterns`.
- **Re-authorization at every step** — `uploadSessionReAuthorizationRequiredOnCreate + signedUrlIssue + multipartPartReceipt + finalize=true`. `abacDenyClosesSession=true` + `reAuthorizationAbacDenyClosesSession=true` forces the session to REJECTED on ABAC denial. The `UploadAuthorizationPort` interface is the only place the application layer calls OpenFGA + ABAC; the executor never mutates another service's domain record directly.
- **Abandoned multipart reaper** — `AbandonedMultipartSweeper` is a pure executor: it never mutates a session, it returns a `SweepResult` describing which sessions to reap + the reason. The application layer applies the `ABANDONED` transition on the persisted session after the re-authorization decision is taken.
- **Closed-set reason codes** — 55 invariant reason codes pinned to the YAML contract; the linter enforces the closed-set. Adding a new code requires an ADR supersession.
- **No cross-service domain import** — the ArchUnit boundary guard (`ServiceBoundaryTest`) blocks accidental coupling to other services. The `MediaInvariants.FORBIDDEN_METADATA_KEYS` set (12 entries) reuses the E6.2/E6.3 `CollaborationInvariants.FORBIDDEN_DOMAIN_COMMAND_FIELDS` map; the linter cross-validates the closed-set.
- **In-memory executor only** — E7.1 vessels the upload lifecycle logic in pure records + executors. The Flyway migration + jOOQ repository + S3 / MinIO signed-URL adapter + Kafka producer/consumer + OpenFeature wiring land in the later E7.x / E11.x sub-epics. The platform `ownership-catalog.md` §2.5 makes this explicit.
- **No new dependency added** — `services/media-service/build.gradle.kts` keeps the existing `spring-boot-starter-actuator + postgres + flyway + openfeature` baselines + the `archunit-junit5:1.3.0` transitive brought in by `service-conventions`. No new Maven coordinates.
- **Audit metadata uses `actorPseudoId` only** — never raw user id / email / DNA. Mandated by `MediaUploadAuditAttributes` + the 9 audit hook toggles in the E7.1 contract. The `auditRequiredKeys` are `actorPseudoId` + `correlationId` + `targetPseudoId`.
- **Single source of truth** — the YAML contract under `contracts/media/upload-lifecycle-policy.yaml` is the cross-service reference; the platform mirror at `platform/helm/genealogy-platform/files/media-upload-lifecycle-policy.yaml` is byte-identical and enforced by the linter. The E6.2 / E6.3 / E6.4 contract files are preserved untouched.
