## Decisions

- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD evolution): ACCEPTED** — every closed-set vocabulary anchored to the YAML contract; the Java enum values are validated by the linter. Adding a new value requires an ADR supersession.
- **ADR-E0.5-01 (Java 21 toolchain): ACCEPTED** — `services/media-service/build.gradle.kts` applies the `java-conventions` + `service-conventions` plugins (Java 21, Checkstyle, ArchUnit boundary guard).
- **YAML contract is the source of truth** — the 11 closed-set vocabularies + the pipeline status transition matrix + the 16 boolean guard rails + the 30 numeric bounds + the 15 invariant reason codes + the 8 audit hooks live in `contracts/media/malware-metadata-pipeline-policy.yaml` and the helm mirror. The Java executor mirrors the contract; the linter enforces it.
- **Platform-component delegation (no re-implementation)** — the ClamAV + Tika adapters are pure ports (`ClamAvScannerPort`, `TikaExtractorPort`). The implementation lands in the worker subproject (E7.x / E11.x); the chart NetworkPolicy + Vault Agent Injector + Istio mesh wiring are reused. Per `design.md` §1 + §11 + §13 + AGENTS.md §5.
- **Sandbox egress allowlist (E2.6 + E2.3 only)** — `sandboxEgressAllowlist=[apicurio, vault-agent]`. The NetworkPolicy enforces the same allowlist at the cluster level. Per `design.md` §11 ("Binary parser không truy cập Internet, chạy non-root, read-only filesystem và resource quota") + AGENTS.md §3 (Istio handles workload identity / mTLS).
- **`linkablePipelineStatuses=[READY]` is a hard invariant** — `MalwareMetadataPipeline.isLinkable(...)` returns true only for `PipelineStatus.READY`. Every other status (including `METADATA_READY` — the "metadata is ready but the asset is not yet committed") is NOT linkable. The linkable-status check is enforced by the linter (`spec.linkablePipelineStatuses MUST equal ['READY']`) and the executor's `isLinkable(...)` method.
- **Signature freshness gate** — `signatureUpToDateRequiredBeforeScan=true` + `signatureStaleFailsScan=true`. `MalwareMetadataPipeline.decide(...)` checks signature freshness BEFORE the scan-outcome check; `STALE` / `UNKNOWN` force `PipelineStatus.FAILED + PipelineFailureReason.SIGNATURE_STALE`. The worker MUST schedule `MALWARE_SIGNATURE_UPDATE` before any subsequent scan.
- **Idempotent pipeline on `pipelineId`** — `pipelineIdempotentOnPipelineId=true`. `decide(...)` refuses a `pipelineId` mismatch between scan + extract. The Temporal workflow uses `pipelineId` as the workflow ID; re-running the same workflow produces the same decision.
- **Output key deterministic + versioned** — `outputKeyDeterministicAndVersioned=true`. `MalwareMetadataPipeline.deriveOutputKey(tenant, asset, version)` returns `media/<tenant>/<asset>/<version>`; bumping the engine version produces a new key without overwriting historical artefacts.
- **Activity heartbeat contract** — `activityHeartbeatSeconds=30` × `activityHeartbeatMultiplier=6` = 180 s. The linter enforces `timeout > multiplier × heartbeat` for every named activity; the contract timeouts are 240/480/240/1800/720 s (MALWARE_SCAN / METADATA_EXTRACT / METADATA_PERSIST / MALWARE_SIGNATURE_UPDATE / CORPUS_VALIDATION).
- **Object-too-large → chunked scan** — `maxInlineScanBytes=536870912` (512 MiB) + `chunkSizeBytes=8388608` (8 MiB) + `maxChunksPerObject=128`. Objects above `maxInlineScanBytes` MUST use ClamAV `INSTREAM` chunked scan; the invariant `PIPELINE_OBJECT_TOO_LARGE_CHUNKED_SCAN` enforces the routing.
- **DNA bucket shield (forward-looking)** — `PIPELINE_DNA_OBJECT_REJECTED` invariant reserves the rejection for DNA objects; the closed-set `dnaBucketPrefixes=[dna/raw, dna/match, dna/consent]` enforcement lands in the E7.4 protected-delivery sub-epic. The pipeline refuses DNA objects here so the E7.4 worker can carry the full DNA bucket prefix shield.
- **Forbidden payload scan** — the linter forbids `credential`, `api[_-]?key`, `private[_-]?key`, `authorization`, `bearer`, `raw[_-]?dna`, `raw[_-]?ssn`, `raw[_-]?passport`, `fastq`, `dna[_-]?raw` in `spec.forbiddenPayloadPatterns`. The scan skips the `forbiddenPayloadPatterns:` list itself (the deliberate literal entries) but reports every occurrence elsewhere.
- **No cross-service domain import** — the ArchUnit boundary guard (`ServiceBoundaryTest`) blocks accidental coupling to other services; `pnpm check:boundary` clean.
- **Audit metadata uses `actorPseudoId` only** — never raw user id / email / DNA. Mandated by `MediaUploadAuditAttributes` (E7.1) + the 8 audit hooks in the E7.2 contract.
- **Helm keys with `-` are parsed as subtraction** — per the E6.1e convention the chart uses `services.media` (no hyphen). The pipeline keys (`timeoutClamavSeconds`, etc.) match the contract field names verbatim.
- **No new dependency added** — `services/media-service/build.gradle.kts` keeps the existing `spring-boot-starter-actuator + postgres + flyway + openfeature` baselines + the `archunit-junit5:1.3.0` transitive. No new Maven coordinates.
- **Single source of truth** — the YAML contract under `contracts/media/malware-metadata-pipeline-policy.yaml` is the cross-service reference; the platform mirror at `platform/helm/genealogy-platform/files/media-malware-metadata-pipeline-policy.yaml` is byte-identical and enforced by the linter. The E6.1e research policy + E7.1 upload-lifecycle policy mirrors are preserved untouched.
