## Decisions

- **ADR-E0.5-08 (Avro + Apicurio + BACKWARD evolution): ACCEPTED** — every closed-set vocabulary anchored to the YAML contract; the Java enum values are validated by the linter. Adding a new value requires an ADR supersession.
- **ADR-E0.5-01 (Java 21 toolchain): ACCEPTED** — `services/media-service/build.gradle.kts` applies the `java-conventions` + `service-conventions` plugins (Java 21, Checkstyle, ArchUnit boundary guard).
- **YAML contract is the source of truth** — the 15 closed-set vocabularies + the derived asset status transition matrix + the 17 boolean guard rails + the 37 numeric bounds + the 16 invariant reason codes + the 5 audit hooks live in `contracts/media/media-processing-pipeline-policy.yaml` and the helm mirror. The Java executor mirrors the contract; the linter enforces it.
- **Platform-component delegation (no re-implementation)** — the libvips / Gotenberg / FFmpeg / Tesseract adapters are pure ports (`LibvipsOptimizerPort`, `GotenbergRendererPort`, `FfmpegEncoderPort`, `TesseractOcrPort`). The implementation lands in the worker subproject (E7.x / E11.x); the chart NetworkPolicy + Vault Agent Injector + Istio mesh wiring are reused. Per `design.md` §1 + §11 + §13 + AGENTS.md §5.
- **Sandbox egress allowlist (E2.6 + E2.3 + E7.3)** — `sandboxEgressAllowlist=[apicurio, vault-agent, image-optimizer, document-renderer, video-encoder, ocr-worker]`. The NetworkPolicy enforces the same allowlist at the cluster level. Per `design.md` §11 ("Binary parser không truy cập Internet, chạy non-root, read-only filesystem và resource quota") + AGENTS.md §3 (Istio handles workload identity / mTLS).
- **`processingInputs=[READY]` is a hard invariant** — `MediaProcessingPipeline.decide(...)` checks the input `PipelineStatus` BEFORE any other gate; a non-`READY` input forces `DERIVED_READY=FAILED` with `PROCESS_ERROR`. The E7.2 linkability invariant carries through to E7.3; the linter enforces `spec.processingInputs MUST equal ['READY']`.
- **ImageMagick is BLOCKED** — `imageMagickFallbackPolicy=NEVER` + `libvipsOnlyForImageTranscode=true` + `imageMagickBlocked=true`. `MediaProcessingPipeline.decide(...)` refuses `ProcessingEngine.IMAGEMAGICK` explicitly with `UNSUPPORTED_DERIVED_FORMAT`; `FALLBACK_NONE` requests force `PROCESSOR_UNAVAILABLE`. libvips is the canonical image engine.
- **EXIF PII scrub is required** — `exifScrubbedRequiredForDerivedReady=true`. The image transcode result MUST report `exifScrubbed=true`; otherwise `DERIVED_READY=FAILED` with `EXIF_PII_LEAKED`. The worker strips EXIF GPS coordinates + camera serial numbers from every derived artefact.
- **Validation gate before DERIVED_READY** — `requireAllValidationChecksPassForDerivedReady=true` + `validationFailNeverYieldsDerivedReady=true`. Every `ValidationCheck` in the report MUST return `PASS`; `FAIL` forces `FAILED` with `VALIDATION_FAILED`. `WARN` is non-blocking; `SKIPPED` is recorded when the check is not applicable (e.g. `CONTAINER_INTEGRITY` on a text file).
- **Partial outcome NEVER yields DERIVED_READY** — `partialOutcomeNeverYieldsDerivedReady=true`. `ProcessingOutcome.PARTIAL` forces `DERIVED_READY=FAILED` with `PROCESS_ERROR`. Partial derived artefacts are not safe to link.
- **Idempotent processing on `processingId`** — `processingIdempotentOnProcessingId=true`. `decide(...)` refuses a `processingId` mismatch between the orchestrator and the validation report. The Temporal workflow uses `processingId` as the workflow ID; re-running the same workflow produces the same decision.
- **Output key deterministic + versioned** — `outputKeyDeterministicAndVersioned=true` + `derivedKeyCollisionFailsPipeline=true`. `MediaProcessingPipeline.deriveOutputKey(tenant, asset, task, engineVersion, attempt)` returns `media/<tenant>/<asset>/<engineVersion>/<task-lowercase>/v<attempt>`; bumping the libvips / FFmpeg / Tesseract / Gotenberg version produces a new key without overwriting historical artefacts. A pre-existing key with a different content hash forces `DERIVED_OBJECT_KEY_COLLISION` → `FAILED`.
- **Activity heartbeat contract** — `activityHeartbeatSeconds=30` × `activityHeartbeatMultiplier=6` = 180 s baseline. The linter enforces `timeout > multiplier × heartbeat` for every named activity; the contract timeouts are 480/960/1800/1800/480/480 s (IMAGE_TRANSCODE / DOCUMENT_RENDER / VIDEO_TRANSCODE / TEXT_OCR / DERIVED_VALIDATION / DERIVED_PERSIST).
- **DNA bucket shield (forward-looking to E7.4)** — `dnaObjectRejected=true` + `PROCESSING_DNA_OBJECT_REJECTED` invariant. `MediaProcessingPipeline.decide(...)` refuses `objectKey.startsWith("dna/")` → `QUARANTINED_RETAIN` with `DNA_OBJECT_REJECTED`. The full DNA bucket prefix enforcement lands in E7.4.
- **OCR language packs pinned** — `ocrLanguagePacksPinned=true`. `OcrLanguage` closed-set pins 5 packs (EN / VI / FR / DE / ZH); the worker MUST pre-resolve the language pack at workflow start and refuse unknown languages. Adding a new pack requires an ADR supersession.
- **Per-task fan-out** — `MediaProcessingPipeline.successAcrossAllTasksYieldsDerivedReady` test pins IMAGE_TRANSCODE→LIBVIPS / DOCUMENT_RENDER→GOTENBERG / VIDEO_TRANSCODE→FFMPEG / TEXT_OCR→TESSERACT routing. Each task has a canonical `DerivedAssetFormat` (`requiredDownstreamFormat(task)`).
- **Forbidden payload scan** — the linter forbids `credential`, `api[_-]?key`, `private[_-]?key`, `authorization`, `bearer`, `raw[_-]?dna`, `raw[_-]?ssn`, `raw[_-]?passport`, `fastq`, `dna[_-]?raw`, `exif[_-]?gps`, `camera[_-]?serial` in `spec.forbiddenPayloadPatterns`. The scan skips the `forbiddenPayloadPatterns:` list itself (the deliberate literal entries) but reports every occurrence elsewhere.
- **No cross-service domain import** — the ArchUnit boundary guard (`ServiceBoundaryTest`) blocks accidental coupling to other services; `pnpm check:boundary` clean. The new `services/media-service/.../processing/` package only imports from `services/media-service/.../domain/` (E7.2 MalwareMetadataPipeline + PipelineStatus) — never from another service's `db/` or `domain/`.
- **Audit metadata uses `actorPseudoId` only** — never raw user id / email / DNA. Mandated by the 5 audit hooks + the 10 audit class/action pairs in the E7.3 contract.
- **Helm keys with `-` are parsed as subtraction** — per the E6.1e convention the chart uses `services.mediaProcessing` (no hyphen). The pipeline keys (`timeoutImageTranscodeSeconds`, etc.) match the contract field names verbatim.
- **No new dependency added** — `services/media-service/build.gradle.kts` keeps the existing `spring-boot-starter-actuator + postgres + flyway + openfeature` baselines + the `archunit-junit5:1.3.0` transitive. No new Maven coordinates.
- **Single source of truth** — the YAML contract under `contracts/media/media-processing-pipeline-policy.yaml` is the cross-service reference; the platform mirror at `platform/helm/genealogy-platform/files/media-processing-pipeline-policy.yaml` is byte-identical and enforced by the linter. The E6.1e research policy + E7.1 upload-lifecycle policy + E7.2 malware/metadata policy mirrors are preserved untouched.
